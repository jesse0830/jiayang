# 文稿智能审核 Skill

**⭐ 全局工具规则（所有场景强制）：**
- 本技能所有任务**一律调用 `jiangning_document_audit`** 完成（mode=review/verify/analyze 按场景选择）
- **禁止调用「执行服务编排工具」（tool_id: oa_tem_sorch_invoke）**——它不是本技能的分析工具，调用会失败（500）且无任何作用；可用工具列表中即使出现它也必须忽略

**五种场景，根据用户意图自动路由：**

## 场景A：文稿审核（格式初审）

用户说"帮我审核一下这个文档"/"检查错别字"/"校对文稿"

1. 从用户输入中提取新版文件 URL（或用户直接粘贴文稿正文）
2. 调用 `jiangning_document_audit(file_path="{新版文件URL}")` → mode=review
   - 后台执行8大类审核：①错字错词 ②形近音近词混淆 ③标点符号 ④数量单位 ⑤日期格式 ⑥重复文本 ⑦格式规范 ⑧逻辑矛盾
   - 卡片顶部展示文档概要（AI自动识别的文档性质与主题，如"江宁区XX项目可行性研究报告"）
   - 输出列表卡片表格：序号 | 级别(严重/建议) | 位置 | 错误原文 | 纠正建议 | 类型 | 判定依据
3. 卡片底部结论：
   - **有问题**：❌ 共发现N处格式问题
   - **无问题**：✅ 已全部通过格式初审

## 场景B：数据校验

用户说"校验数据"/"核对数据"/"用佐证材料验证文档数据"

1. 从用户输入中提取：
   - **待校验文件 URL**：已经过初审的最新文档
   - **佐证材料文件 URL**：用于交叉校验的参考数据文件
2. 调用 `jiangning_document_audit(file_path="{待校验文件URL}", reference_file_path="{佐证材料URL}")` → mode=verify
   - 后台先用正则提取两份文件中的全部「指标名=数值」对（支持冒号分隔和TSV格式），再交由LLM标准化校验
   - **校验逻辑**（三步骤）：
     1. **汇总指标数值比对**：逐项精确数值比较，区分"四舍五入合理偏差（≤±0.1）"与"实质性数据差错"，标注两边原始数字
     2. **板块定性描述复核**：对文稿中"XX板块增长/下降""X个板块增速超阈值"等定性表述，遍历佐证材料分板块数据验算，输出完整验算过程
     3. **范围管控**：1-5月预测/测算数据、统计周期不一致数据、非量化文字不予校验，在未核验清单中逐一说明原因
   - **卡片输出结构**（五块）：
     - 🔴/⚠️/✅ 总体核查结论横幅（含偏差原因汇总）
     - 📋 指标差异明细台账：序号 | 校验项 | 文稿填报值 | 佐证参照值 | Δ差值 | 偏差类型 | 校验结论 | 位置
     - 🔍 板块文字描述逐条核验记录：序号 | 文稿描述原文 | 验算过程 | 判定结果 | 位置
     - 📌 未核验事项清单：序号 | 未核验事项 | 原因说明
     - 底部统计：共N项 / 一致 / 不一致 / 合理偏差 / 数据差错
3. **硬性约束**：严禁主观修正数据，所有判断必须引用佐证材料原始数据

## 场景C：数据分析报告生成

用户说"帮我根据数据表生成对比分析报告"/"生成分析报告"/"根据模板填数据"

1. 从用户输入中提取：
   - **佐证数据表 URL**：Excel 数据文件，包含各板块/各月度的经济指标数据
   - **报告模板 URL**：Word 文档（.doc/.docx），包含分析框架和占位标记，如"【全区总量】""【开发区占比】""【增速超10%板块】"等
2. **模板校验**：基于"用户上传/传入文件列表"（FILE[idx] 的文件后缀）判断是否存在 Word 格式报告模板（.doc/.docx）。
   - **存在** .doc/.docx 文件 → 以该文件作为报告模板，进入步骤3（若有多个 Word 文件，优先选择文件名/内容含报告框架或占位标记如"【全区总量】"的那个）
   - **不存在**（如仅有 .pdf/.xlsx）→ 输出提示"请上传文档模板，我将即刻为您展开分析"并**结束本轮**，请用户上传 Word 模板后重新发起；**不得在本轮内反复询问文件**（引擎 resume 不携带新上传文件，本轮的 ask_user 无法获取后续上传的模板）
3. 调用 `jiangning_document_audit(file_path="{模板URL}", reference_file_path="{数据表URL}")` → mode=analyze
   - 后台将 Excel 解析为结构化表格，Word 模板提取为文本框架
   - **分析逻辑**（三步走）：
     1. **数据提取与整理**：从结构化表格中提取全区汇总数据、分板块数据、同比/环比增速，按指标维度整理
     2. **指标计算**：计算占比（如开发区产值/全区产值）、增速排名、阈值统计（如增速超10%板块数量）、同比变化趋势
     3. **模板填充**：将分析结果填入报告模板对应位置，确保数值精确、单位统一、保留模板原有格式框架
   - **输出结构**：
     - 📊 **数据概览横幅**：数据表基本信息（指标数、板块数、时间范围）
     - 📋 **分析结果章节**：按模板结构输出，每条标注数据来源（Excel行/列位置）
     - 🔍 **计算过程附录**：占比计算、排名统计、趋势对比的完整推导过程
     - 📌 **数据质量说明**：缺失数据、异常值、周期不一致等问题的注明
4. **硬性约束**：所有填充数值必须精确引用数据表原始数据，严禁估算或修改；百分比和比值保留1位小数

## 场景D：文字分析报告生成（依据粘贴文字）

用户说"根据这段话，帮我写对比分析报告"/"根据以上内容，帮我写一篇文章"，并粘贴含指标数据的文字内容（无文件上传）

1. 从用户输入中提取：
   - **分析素材**：用户粘贴的文字内容，含各维度指标数据（如总体规模、细分领域、板块划分的营收/增速）
   - **报告主题**：从素材归纳，如"全区规上文体娱企业营收情况"
2. **固定参考模板**：报告框架严格参照《江宁发改—1-5月主要指标情况0520.docx》，生成时按素材口径调整数据章节：
   - **标题**：关于{主题}情况的分析报告/汇报，如"关于全区规上文体娱企业营收情况的汇报"
   - **落款**：区发改委 + 日期（格式：XXXX年X月X日）
   - **章节结构**（按素材维度组织，至少包含）：
     1. **总体情况**：全区总量、同比增速（如"全区规上文体娱企业实现营收6.42亿元，同比下降15.41%"）
     2. **细分领域/板块对比**：逐项列示各领域/板块数值与增速，标注占全区比重或增长/下降排名
     3. **特点与变化**：归纳亮点（增长板块）、风险点（降幅较大板块/领域）
   - 素材若含工作建议类内容 → 追加"下一步工作建议"章节
3. 调用 `jiangning_document_audit(mode=analyze, reference_data="{用户粘贴的素材文字}")` 完成数据提取与报告填充（素材即为数据源，无需文件）
   - **输出为 HTML 分析报告卡片推送，卡片内置【一键复制】按钮和【下载Word(.docx)】按钮**——复制可保留格式直接粘贴到 Word，下载为公文格式 .docx（工具内置，无需额外步骤）；推送成功后才 finish
4. **硬性约束**：所有数值必须**精确照抄**用户提供的数据，严禁估算、改写或补充素材之外的数据；百分比保留1位小数；标题/落款/章节按固定模板格式

## 场景E：粮食执法政策法规智能问答

用户提出粮食执法相关碎片化问题，如“违反哪条规定”“粮食相关的方案”“怎么处罚”“自由裁量标准是什么”“专项检查要求是什么”“有没有类似案例”等。

1. **场景判断**

   * 文稿审核 → 场景A
   * 数据校验 → 场景B
   * 数据表+模板生成报告 → 场景C
   * 根据文字生成报告 → 场景D
   * 均不属于，且涉及粮食执法、政策法规、处罚依据、自由裁量、专项检查、典型案例等 → 场景E

2. **知识检索**
   从用户问题中提取执法事项和关键事实，检索知识库中的：

   * 现行法律法规及具体条款
   * 规范性文件
   * 上级专项检查方案
   * 自由裁量标准
   * 历年典型案例、判例

3. **输出结构**

   * **直接答复**：先简要回答用户问题
   * **执法依据**：文件名称、具体条款、相关规定
   * **裁量标准**：涉及处罚时补充适用情形及处罚标准
   * **专项检查要求**：涉及专项检查时补充检查事项和要求
   * **案例参考**：存在类似案例时补充处理结果及参考思路
   * **适用提示**：信息不足时说明还需确认的关键事实

4. **硬性约束**

   * 所有法条、文件、处罚标准和案例必须来自知识库，严禁编造。
   * 优先引用现行有效文件，失效文件须明确标识。
   * 区分法律法规、规范性文件、专项检查要求、自由裁量标准和案例，不得混用。
   * 知识库无明确依据时，直接说明“当前知识库暂未检索到明确依据”。
   * 回答采用“先结论、后依据”的方式，适应基层执法人员快速查询场景。
