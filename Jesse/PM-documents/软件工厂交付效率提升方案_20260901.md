# 软件工厂交付效率提升方案（讨论稿 v0.1）

> 用途：周四上午向方总汇报，方总转报刘超
> 依据：2026-09-01 会议《交付效率提升路径》（参与人：田聪）＋软件工厂运营数据
> 状态：讨论稿，待逐项打磨

## 一、会议核心结论（速览）

1. **效率低不是人的问题，是工具和协作方式的问题**——以工具为核心重建交付体系，不靠招聘高手
2. **目标倒排**：以"48小时响应一个模块需求交付"为目标，倒推各环节耗时，找出超时点
3. **试点先行**：以"备股"项目试点，验证提效30%（设计复用率50%），形成可复制的全局方案
4. **图形化是刚性需求**：业务流程设计必须图形化输出，禁止仅文字描述沟通
5. **基线能力投入不计入项目成本**：AE/DE集中梳理问题→一次性提交研发→纳入月度版本迭代

## 二、现状诊断

### 2.1 堵点面（会议共识）

| 堵点 | 具体表现 | 后果 |
|---|---|---|
| 配置工作量超标 | 2人天、3人天甚至5人天 | 无法满足48小时响应 |
| 文档协作 | AE与DE依赖文档沟通，阅读理解成本高，应届/大专背景挑战大 | 信息传递断层频发 |
| 复杂视图开发 | 弹窗子表视图编写耗时一上午 | DE侧耗时大户 |
| 多页面联动 | 1个表单字段变更涉及12个页面同步调整 | 变更成本高、易漏改 |
| 多模块关联 | 督办任务调整牵涉3个功能模块独立调整 | 影响范围难评估 |
| 高字段密度 | 200+字段表单手动配置 | 建模+配置双重耗时 |
| 建模质量 | 建模不合理→视图/配置复杂度上升；无工具辅助判断建模正确性 | AE门槛被迫拉高至L3 |
| 历史包袱 | 个别案例用存储过程等难维护方式实现 | 长期维护成本高 |

### 2.2 根因归纳（三个"太"）

- **复用度太低**：组件、模板、场景沉淀不足
- **沟通成本太高**：文档传递信息，阅读理解式协作
- **输出太复杂**：建模质量依赖个人能力，工具无图形化、无逻辑控制、无服务编排

## 三、配置耗时归因分析

**核心问题**：为什么同样是一个模块配置，有的0.5人天，有的却要5人天？

以"48小时倒推"的思路（方总："理论上你拿到的所有清单，应该都是0.5、1、0.5、1这样的"），对每个超时场景做三问归因：

| 归因维度 | 问题 | 判断方法 | 对应策略 |
|---|---|---|---|
| 业务复杂度 | 业务本身是不是真复杂？（200+字段、多模块联动、复杂流程） | 按字段数/模块数/流程节点数评估 | 真复杂 → 接受，走L3专项 |
| 工具能力 | 是工具不支撑还是业务复杂？（无模板、无图形化、变更手动） | 同类场景能否复用已有资产 | 工具债 → 模板化/生成器补齐 |
| 人员匹配 | 是能力不够还是任务太难？（新人被派高复杂度任务） | 对照L1/L2/L3分级 | 错配 → 分级派单，专项小组兜底 |

**判定矩阵**（业务复杂度 × 工具能力 → 对策）：

| 业务复杂度 \ 工具能力 | 工具成熟 | 工具不足 |
|---|---|---|
| 低复杂度 | 0.5~1人天（目标态） | 模板化即可解决，属工具债 |
| 高复杂度 | 标准化拆分+组件复用 | 场景攻坚，备股试点验证 |

**三条对策原则**：
1. 能工具化的工具化：模板复用、设计态生成、变更联动
2. 能简化的简化：标准件、公共组件、图形化流程表达
3. 剩下的真实复杂度：明确归L3，专项投入，不硬压人天

## 四、配置能力分级体系（L1/L2/L3）

**核心问题**：配置能力应有级别区分，不同级别应对不同业务复杂度，避免人岗错配。

| 级别 | 应对业务复杂度 | 典型场景 | 人员要求 | 工具支撑 |
|---|---|---|---|---|
| L1 | 低：标准表单、简单列表、单页面 | 基础增删改查页面 | 初级/应届，培训1~2周可上岗 | 模板直接套用 |
| L2 | 中：业务流程、数据看板、页面联动 | 审批流、统计看板、联动修改 | 中级，2~3年经验 | 图形化配置+组件复用 |
| L3 | 高：200+字段、多模块关联、复杂逻辑 | 复杂建模、督办多模块、服务编排 | 高级/专家 | 工具补齐+专项攻坚 |

**分级的意义与运作**：
- **人岗匹配**：业务复杂度分级 → 任务按级别派单，杜绝"初级人员承担高复杂度任务"（会议共识）
- **降门槛**：工具补齐后，L1/L2 应能承接大部分场景，L3 聚焦少数真复杂场景——当前"AE门槛被迫拉高至L3"正是工具不足的信号
- **专项小组**：非功能性需求（SSO等）不分级派发，统一交专项小组
- **动态认证**：人员级别定期评估，与考核联动（配合DE多维度考核优化）

## 五、提效路径总览（双轮驱动 + 机制保障）

```
        ┌─────────────────────────────────────┐
        │       48小时响应（目标倒排）            │
        └─────────────────────────────────────┘
                 ↓ 双轮驱动
   ┌─────────────────────┐  ┌─────────────────────┐
   │  轮1：工具改进         │  │  轮2：协作模式优化     │
   │  ·交付中心图形化输出    │  │  ·AE/DE工具协同替代   │
   │  ·业务流程图自动生成    │  │   文档沟通           │
   │  ·需求→设计态一键生成   │  │  ·角色能力分级管理    │
   │  ·变更影响范围识别      │  │  ·非功能需求专项小组   │
   │  ·版本管理/黑盒消除     │  │  ·强PM统筹结对（可复制化）│
   └─────────────────────┘  └─────────────────────┘
                 ↓ 机制保障
   ·基线能力需求集中提交研发，月度版本迭代，不计入项目成本
   ·工时填报审批（合契枢优化）
   ·考核牵引（DE多维度考核、bug日清）
```

## 六、分角色落地举措

### PM（提效杠杆：标准化 + 抽身执行）
- 输出常见场景模板库（业务流程/数据看板/非功能需求），配合备股试点
- 以48小时为目标拆解项目计划，各环节设耗时预算，超时点预警
- 借鉴帛飞特模式：强PM统筹AE+DE结对，但重点是把"靠人"沉淀为"靠工具"
- 机制：工时审批权归PM（解决超8h填满、财经无法核算问题）

### AE（提效杠杆：降门槛 + 复用）
- 高频业务场景梳理：业务流程、数据看板、非功能需求分类建模板
- 推动交付中心原型→设计态能力补齐（逻辑控制/服务编排/数据治理）
- 按L1/L2/L3能力分级派单（详见第四章），工具补齐后AE门槛从L3降到L1/L2可承担
- 非功能性需求（SSO等）交专项小组，不让新人/初级承担

### DE（提效杠杆：瓶颈突破，重点投入）
- 复杂视图、多页面联动、多模块关联三大耗时场景逐个突破
- 配合交付中心试用版，把"1字段变更12页面"压到工具自动联动
- 组件/模板沉淀，设计复用率目标50%
- 考核优化：从单一bug日清，走向"质量+效率+复用"多维

### IE（提效杠杆：资产复用 + 自动化）
- 测试资产复用库（用例、脚本沉淀）
- 自动化回归，支撑48小时交付下的质量保障
- 环境准备标准化，减少联调等待

## 八、备股试点计划

- **目标**：验证提效30%；设计复用率50%；全流程可监控；产出标准化执行模板
- **路径**：
  1. 梳理备股高频业务类型（业务流程/数据看板/非功能需求）
  2. 分析各场景主要耗时环节，识别共性问题归类解决
  3. 交付中心本周发布试用版，备股团队实际使用
  4. 问题集中梳理一次性提交研发，纳入月度版本迭代（不计入项目成本）
- **分工**（按会议，人名已更正）：

- **验证方式**：试点前后同类场景人天对比，出具量化报告
