# 实例：HC 缺口表截图提取（2026-08-05 会话）

输入：720x280 PNG（用户从聊天里发的 `@image:.../composer-images/composer_2026-08-05_10-39-50-391_7a13de.png`），内容是软件工厂 HC 缺口表（地点 × 角色）。

## 完整命令序列

```bash
# 1. 确认图片
file "<path>.png" && sips -g pixelWidth -g pixelHeight "<path>.png"
# → PNG image data, 720 x 280

# 2. 3x 放大
sips -z 840 2160 "<path>.png" --out /tmp/hc_big.png

# 3. 整体 OCR（第一次 psm 6 就基本可用，但行数多时数字可能错位）
tesseract /tmp/hc_big.png /tmp/hc_ocr -l chi_sim+eng --psm 6

# 4. tsv 模式按坐标提取每个单元格
tesseract /tmp/hc_big.png /tmp/hc_tsv -l chi_sim+eng --psm 6 tsv
# tsv 列: 6=x, 7=y, 10=confidence, 11=text；按 (y,x) 排序重建行
```

提取结果（y 坐标分组确认行归属）：

| 地点 | PM | AE | DE | IE | 总计 |
|---|---|---|---|---|---|
| 南通 | 4 | 4 | 0 | 0 | 8 |
| 成都 | 4 | 5 | 3 | 3 | 15 |
| 无锡 | 2 | 4 | 12 | 10 | 6 ⚠️ |
| 南京 | 4 | 40 | 6（数据开发） | 0 | 72 ⚠️ |
| 总计 | 14 | 53 | 21 | 13 | 101 |

## 验证逻辑（关键）

**列求和全部吻合**：PM 4+4+2+4=14 ✓、AE 4+5+4+40=53 ✓、DE 0+3+12+6=21 ✓、IE 0+3+10+0=13 ✓，总 HC 缺口 = 101。

**行总计矛盾**：无锡行内求和 2+4+12+10=28 ≠ 打印的 6；南京行内求和 4+40+6+0=50 ≠ 打印的 72。

## 定点重识别（排除 OCR 错误）

```bash
# 裁剪无锡行总计格（原图坐标：y≈148-178, x≈540-620）
sips -c 30 80 --cropOffset 148 540 "<path>.png" --out /tmp/wx_total.png
sips -z 600 1600 /tmp/wx_total.png --out /tmp/wx_total_big.png
tesseract /tmp/wx_total_big.png /tmp/wx_ocr --psm 7   # → 6（仍是 6）

# 南京行总计格（y≈190-220）
sips -c 30 80 --cropOffset 190 540 "<path>.png" --out /tmp/nj_total.png
sips -z 600 1600 /tmp/nj_total.png --out /tmp/nj_total_big.png
tesseract /tmp/nj_total_big.png /tmp/nj_ocr --psm 7   # → 72（仍是 72）
```

结论：像素级放大后仍是 6 和 72，**OCR 没错，源表自身行总计与行内数据不一致**（列合计却完全自洽）。

## 处理方式

不猜、不修表。把完整识别表 + 验证结果 + 矛盾点交给用户确认（"无锡的总计到底是 6 还是 28？南京到底是 72 还是 50？还是总计列有特殊含义？"）。用户确认后再继续分析。

## 修订版核对（同日 v2 / v3）

用户随后又发来两版修改（11:55:28 与 12:13:06），每版都**重新 OCR 全表**、独立验证、并与上一版做 diff：

**v2（11:55:28，修正矛盾版）** — 与 v1 相同 4 区域，无锡总计 6→28、南京总计 72→50，修正后行列全自洽，总计 101 ✓。结论：上一轮的矛盾点已修复。

**v3（12:13:06，区域重分配版）** — 扩到 6 区域：新增温州（PM4 AE3 DE2 IE1=10）、惠州（PM1 AE0 DE1 IE0=2）；无锡 PM/AE 清零只剩 DE10+IE10=20；南通 PM4→2/AE4→7；成都 15→11；南京 AE40→39。列合计仍 14/53/21/13，总计仍 101 ✓。

**可复用要点（修订版）**：
- 每版重新 OCR，不要拿旧结果改几个格——用户可能大改。
- 验证三件事：行求和、列求和、总计行，三者全平才算"正确"。
- 回复格式：本版自洽性 + 与上一版的变化清单（新增/删除行、变动的数字、总计是否变）。
- 总计不变不代表没改——区域间重分配时总和恒 101，diff 才是用户关心的。

## 可复用要点

- 坐标换算：tsv 的 x/y 是放大后坐标，裁剪原图时除以放大倍数（3x → 540/3=180 等）。
- 判据：**列合计一致 → 单元格可信**；**行总计矛盾 → 先查 OCR，再问用户**。
- 带括号注释的单元格（`6 (数据开发)`）数字与注释都要保留，别丢注释。
