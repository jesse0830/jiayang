# OA 报销数据抓取 — 补充坑点和技巧（2026-06 对话）

## 新发现的模块：左侧菜单「我发起的」

除了员工报销（出差报销/个人报销/招待报销(旧)标签页）和招待报销申请之外，左侧菜单还有一个重要的查询入口：

### 「我发起的」菜单项

**用途**：查询用户个人发起的全量流程，不分报销类型（包含出差申请、招待报销、出差报销等所有类型）

**列结构**（索引从0开始）：
- c[0] = 事件类型（如"招待报销"、"费用报销"、"出差申请"）
- c[1] = 事件名称（含金额，格式如 "杨嘉阳 1280.00 项目 20260608365"）
- c[2] = 摘要（如项目名称）
- c[3] = 创建时间
- c[4] = 更新时间
- c[7] = 流程状态（"处理中" / "结束"）
- c[8] = 业务状态（"直接主管审批" / "经办会计审批" / "出纳付款" / "结束"）

**金额提取**：金额嵌在 c[1]（事件名称）的文字中，格式为 `"杨嘉阳 <金额> <类型> <编码>"`，需要正则解析。

**适用场景**：当你需要查询**某个特定用户**（如杨嘉阳）的个人报销进度时使用。不适合做全局统计（因为只显示当前登录用户的发起记录）。

**注意**：此页面**不按报销类型分页**，而是按时间倒序排列所有流程。分页数是全量流程的分页，不是按报销类型。

## 新分页陷阱：「跳跃式分页」

本次会话发现一个新坑点：OA 的分页控件在点击不同页码时，显示的页码集可能**跳跃变化**。

具体表现：
1. 第一次进入「我发起的」页面时，分页显示为：1,2,3,4,5,20（共20页）
2. 点击第1页后返回再次检查，分页变为：1,16,17,18,19,20
3. 中间页（6-15页）在分页控件中不可见

这意味着**分页控件显示的是"上下翻页窗口"而非全量页码列表**。第1页的内容可能包含了最新的记录，第16-20页是历史记录（已结束的）。

**解决方案**：
- 如果只需要最新数据（如未报销的记录），第1页通常就够了（按创建时间倒序）
- 如果需要全量数据，需要：
  1. 点击下一页按钮（`.ant-pagination-next`）多次，逐页翻完
  2. 或使用 .ant-pagination-item 的文本内容判断实际页码范围
  3. 注意 `.ant-pagination-next` 按钮在最后一页会添加 `disabled` 类

## 个人视角查询的技巧

当用户想查自己还有多少钱没报销时，最优路径不是去员工报销模块做全局统计，而是：

1. 左侧菜单 → 「我发起的」→ 查看第1页（最新的处理中的记录）
2. 关注业务状态为 `直接主管审批`、`经办会计审批`、`出纳付款` 的记录
3. 从 c[1] 中提取金额相加

**与全局统计的比较**：
- 全局统计（员工报销三个标签页）：可以看到全公司所有未报销数据，但数据量大
- 个人视角（我发起的）：只看自己的，适合快速查个人欠款
- 两者结合才能完整分析

## 新增陷阱：多步翻页后「我发起的」分页器消失

**本会话发现：** 手动用 `browser_click` 在「我发起的」页面逐页翻页 3-4 次后，`.ant-pagination` 组件从 DOM 中完全消失，翻页能力失效。

**关键影响：** 此前该页面的翻页数量巨大（208条/21页），手动逐页翻页不可行。

**解决方案：** 详见 `references/oa-portal-data-extraction.md` → 多步翻页时 pagination DOM 完全消失。推荐用一次性 JS async function 或 delegate_task 子代理完成翻页。
