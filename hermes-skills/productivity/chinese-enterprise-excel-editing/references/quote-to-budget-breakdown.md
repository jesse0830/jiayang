# 报价单 / 申报方案 → 分项预算表（功能点法 / 工作量法）

## 场景与判定

用户给 (a) 一份**定稿的 Word 报价单或项目申报方案 .docx**，(b) 一张 **Excel 预算表模板 .xlsx**（典型两个 sheet：**功能点法**、**工作量法**），要求"把报价单里软件部分的 N 大系统拆成明细，按模板填进 Excel"。

**交付物是填好的 .xlsx 本身**，不是文本清单、不是建议书。产出落用户工作目录（`99-软件工厂/98 hermes`），文件名带 `_已填充_<YYYYMMDD>`。

## 步骤

1. **先读模板列头，再动笔**：`openpyxl` 打印 `wb.sheetnames`、每表 dimensions/max_row、表头行、合并单元格、列宽；**列头逐字抄下作正确性判据**。不新建 sheet、不改模板布局，只填明细行。
2. **读源 docx 成可 grep 的落盘文本**：写 `/tmp/docx_dump.py`，按 `行号 | P{段落号} | style | 文本` 逐段输出，表格行输出为 `T{表号}R{行号}: cell || cell || cell`，重定向到 `/tmp/docx_dump.txt`。长文档的输出必被工具/上下文截断，落盘后 grep 或分段读，任何数字都能一次 grep 回原话（`软件开发费`、`总投资`、`合计`、`成本指标`、`人工费用标准`、`×2%` 之类），不必反复解析 docx。
3. **先建口径表再填**：把源文件所有金额列全（各系统小计 / 软件开发小计 / 实施服务费分项 / 其他费分项 / 总投资 / 成本指标），标注每个数字出现在哪些表段，交叉核对后才开始填（清单见下）。
4. **拆分基数先向用户确认，只取"软件开发费"口径**："总投资 / 软件开发费 / 各系统小计"是三个不同的数，用户要的通常是**软件开发费小计**；不能按总投资推算，也不能沿用上一版（用户会直接否掉重做）。
5. **单价表先核实原文再定级**：grep 出"工程技术人员月人工费用标准"一节的原文，逐字抄下**人员类别 × 档位**的单价，**确认到底有几类人员几档**（实测常见 2 类人员 × 普通/初级/中级/高级 = 8 个单价；曾误以为存在第三类而卡住，实际没有——别靠记忆或压缩摘要里的数字）。
6. **金额是权威值**：模块行金额取报价单口径，人月 / 功能点**由金额 ÷ 该行单价反算**；子系统小计与合计用 Excel 公式（SUM / 相加），便于用户当场核；数字不带千分位。
7. **表底加 注1..注N**：计量单位、换算口径、系数取值理由、口径差异说明，以及**加权均价与源文件基准均值的偏差**（评审最爱问"你单价怎么定的"）。
8. **两段独立校验**：① 回读生成文件重算（子系统小计 = 模块累加、合计 = 各小计之和）与源文件口径逐一对齐，并逐行验 `人月 × 单价 = 小计`、单价属于源表档位集合；② 另一个脚本单独打开文件打印 sheet / 表头 / 行列数 / 合计公式，确认模板布局未被破坏。

## 布局模板（可用形态）

- 表头 2 行（大标题合并单元格 + 列头行），数据从第 3 行起，`ws.freeze_panes = "A3"`。
- 分组结构：**系统分组行**（跨列合并写"一、XX 子系统"）→ 若干**模块行**（序号 / 模块名 / 功能点 / 人月 / 小计）→ 该子系统**小计行**（公式 SUM）。
- **工作量法 sheet 另立"人员类别 / 级别 / 单价"列**，让每行单价可见（差异化定价必须能被评审逐行看到）。
- 末尾**合计行** = 各子系统（及数据整合接口等平行小计）相加，必须与源文件口径数字一致。
- 可再加一张**"单价依据" sheet**：把源文件级别单价表原样摘录（人员类别 × 普通/初级/中级/高级）＋一行取用说明，用户/评审一眼能对上号。
- 表底 `注1..注N` 用合并单元格跨表宽写。
- 数字格式：金额 `0.00`、功能点 `0.0`、人月 `0.0`；全表细边框；字体与模板一致。

## 计价口径：级别单价分档（用户硬要求）

**"单价怎么都是一个价"是用户会直接提出的驳回理由**：全表统一单价（例如一律 1.92 万元/人月）不符合要求。规则是**按功能难易程度给每行定级、取该级单价、人月随难度浮动**。

源方案里通常有两层价：**级别单价表**（人员类别 × 普通/初级/中级/高级）与**综合基准单价**（如 1.92 万元/人月）。后者原文一般明说是"初/中/高级人员月人工费用的**加权均值**"，用于功能点测算法口径；系统集成部署、数据治理、接口实施这类按**级别单价**计取。所以：逐行单价＝级别单价；1.92 只作总额一致性校验与表底注，**不要写进任何一行的单价列**。

### 难度分级映射（默认口径，源文另有规定从其规定）

- 简单 → 普通；一般 → 初级；较复杂 → 中级；复杂 → 高级。
- 开发功能类模块取"信息系统分析工程技术人员"档位；接口对接、数据整合、集成部署等实施类取"数据分析处理工程技术人员"档位（**按源表实际类别名写，别硬编码猜测**）。
- 每个模块同时给出**级别基准人月**（简单 1.25 / 一般 1.9 上下 / 较复杂 2.2~2.8 / 复杂 3.9~7 视模块规模）——它只是权重，不是最终人月。

### 金额归一分摊公式（保证"总额不变 + 单价分档"）

金额是权威值，所以先用权重算出各模块占比，再归一到子系统金额，最后由金额反算人月：

```python
raw  = sum(BASE_PM[level] * RATE[(cat, level)] for ...)   # 模块级权重
k    = SUB_MONEY[key] / raw                               # 归一到子系统权威金额
money[r] = round(BASE_PM[level] * RATE[(cat, level)] * k, 2)  # 尾差落最大模块
pm[r]    = round(money[r] / RATE[(cat, level)], 2)        # 人月由金额反算
fp[r]    = round(pm[r] * 8.0, 1)                          # 功能点由人月反算
```

**加权均价自检**：`Σ金额 ÷ Σ人月` 应落在源文件写的综合基准单价附近（实测分档后 1.9181 vs 源文 1.92，偏差约 −0.1%）——这条对上说明难度定级与级别配比自洽，**写进表底注**（"级别配置的加权平均单价 X 万元/月，与方案第九章 Y 万元/月的加权均值一致，说明按难度分档取价后总价水平未变"）。若偏差大，是级别配比不合理，先调级别再交付。

## 两法换算约定

- **功能点法**：`人月 = 金额 ÷ 该行单价`，`功能点 = 人月 × 生产率`。每行只对一个自由量取值，另一个必须由它算出，**不许人月和功能点两个都手写**（否则行内自相矛盾，评审一眼看穿）。
- **工作量法**：列 工作项 / 人员类别 / 级别 / 人月 / 单价（万/月）/ 小计（万元），`小计 = 人月 × 单价`，逐行可核。
- **常见取值**（以项目当期编制规范为准，别当常量硬编码传播）：生产率 **8.0 功能点/人月**；复用度 / 调整系数默认 **1.00**；综合基准人月费用（如 1.92 万元/人月）**仅作校验基准**，逐行单价一律取级别单价表档位值。
- **两张表要联动重算**：换了计价口径，按旧统一单价算出来的人月合计、功能点合计（例：216÷1.92=112.50 人月、×8=900 功能点）全部作废，必须重算并把注里引用它们的数字一并改掉，否则新旧口径混在同一份表里。
- **尾差**：金额与折算人月/功能点存在四舍五入差 → 注里写明"以金额为准"。
- **公共平台不重复计费**：引用政务云、统一身份认证、电子证照、政务共享平台、区域门户等既有能力时，只计**对接开发量**，不重复计平台费用，系数仍取 1.00 并在注里说明理由。

## 口径对账清单（填表前必做，也是最大的坑）

把下列每项的数字 grep 出来，核对是否互相打架：

1. 各子系统小计之和 **vs** 源文件"软件开发费"小计。
2. "软件开发费"小计的**构成说明** vs 其明细表**实际列的行**——常见小计里多算了"系统集成与部署""等保测评与安全加固"这类非开发项。
3. "系统集成与部署"：是否**同时**出现在软件开发小计和实施服务费明细里（重复计列）。
4. "等保测评与安全加固"：是否**同时**出现在软件开发小计和其他费里（重复计列）。
5. 按百分比计提的费用（验收测评费 = 项目建设费 × N%、信创评估费 = 软件部分 × N%）的**基数**与小计是否对得上（软件开发费一改，这些费率项要联动重算）。
6. 正文"总投资估算" vs 绩效/成本指标里的"项目总投资控制在 ××万元以内"。
7. 资金构成段落（如"定制软件开发费（含数据整合、系统集成、测评加固）×××万"）与明细表是否一致。

**任一冲突 → 不静默改数。** 政务申报数字不可编改：本表按**纯口径**填（只含子系统 + 数据整合/接口），重复项留在其真正归属的费用类别里，差额写进表底注；回复中明确列出重复项、超限项、以及**受影响的联动数字清单**（所有以该小计为基数的费率、总投资、占比），给用户 A/B 方案（A 改明细压总额 / B 保原数补行）让他拍板，拍板后再联动改报价单正文。**不要自己选一个方案就改**。
