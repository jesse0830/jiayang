# 中文企业 Excel 表格安全编辑（openpyxl）

适用于用户反复出现的中文企业工作簿编辑任务：绩效考评表、人员名单、花名册等。核心原则：**先只读分析确认，再备份，再修改，改后验证**。用户对数据完整性要求极高，不允许推断/编造数据。

## 触发条件

- 用户要求"处理一下那个 excel"、"补充入职时间/某列"、"删掉重复的"、"核对 sheet1/sheet2 差异"、"看看谁在 A 表有 B 表没有"
- 用户要求"把 X.xlsx 里打过绩效/填好的数据合并到 Y.xlsx 里"（跨工作簿合并，见下方专门章节）
- 用户给一份 Word 报价单 / 项目申报方案 + 一张 Excel 预算表模板，要求把其中 N 大系统“拆成明细按模板填进 Excel”（→ 见下方“报价单/方案 → 分项预算表模板填充”，方法与口径见 `references/quote-to-budget-breakdown.md`）
- 用户对已交付的分项预算表说"**单价怎么都是一个价**"／要求"按功能难易程度把单价和人月改一下"（→ 见下方第 5 条与 `references/quote-to-budget-breakdown.md` 的"级别单价分档"）
- 涉及两个 sheet 或多张表交叉核对人员/数据

## 标准工作流

1. **只读分析先行**：`openpyxl.load_workbook(path, data_only=True)` 读清表头、数据起始行、合并单元格、列含义，打印关键结论给用户确认。
2. **备份必做**：改动前 `shutil.copy2(path, path.replace(".xlsx", "_备份_<标签>.xlsx"))`，标签写清本次改动（如 `_备份_删重前`）。
3. **修改用保留格式模式**：`load_workbook(path)`（不带 data_only！）再改，否则公式丢失、格式损坏。
4. **改后验证**：重新 `data_only=True` 加载，核对行数、填充数量（如 57/90 → 79/90）、断号情况。

## 跨工作簿合并数据（绩效/评语/任意列）

用户常把同一个月的工作簿拆成部门版（如《...-配置开发部.xlsx》已打绩效）和总版（《....xlsx》绩效区空白），要求\"把这个里面打过绩效的合并到主文件中\"。

1. **只读读两边结构**：源文件表头/数据起始行/绩效列位置 vs 主文件表头。两表列序可能完全一致（源文件就是主表拆出来的），但**必须实读确认**，别凭文件名猜。
2. **匹配键优先 (工号, 姓名) 联合键**：两表都有工号列时用联合键最可靠（能正确命中同名不同人、状态冲突的同名）。源文件若有重复行（本会话源文件 100 有姓名行、去重后 60 人有绩效），按联合键 dict 去重后再合并。
3. **只合并\"有数据\"的行**：列 11-16 绩效区 `any(v is not None and str(v).strip()!=\"\" for v in perf)` 才算打过绩效；没数据的人**留空**，不写 None 覆盖、也不动。
4. **改前备份**：主文件 `_备份_合并绩效前.xlsx`。
5. **写入后验证三件套（合并版）**：① 匹配数 = 源有绩效人数（去重后）；② 未找到列表为空（有未找到必须列出给用户）；③ 重读两边逐行比对绩效值 `dperf != sperf` 得 0 mismatch。三条全过才算完成。

## 同一工作簿内跨 sheet 合并（部门版 Sheet → 汇总表 Sheet2）

与跨工作簿不同：**主文件就是同一个 .xlsx，Sheet2 是汇总表（已含全部人员行），源 sheet 是某部门的绩效版**。用户说"把 sheetX 里 XX 部的绩效放到 sheet2 里"。

1. **先只读确认两 sheet 结构**：Sheet2 常见三层表头（R1 大标题"2026年X月月度绩效考评"合并 K1:P1、R2 "绩效考评结果/绩效考评评语"、R3 子表头"核心绩效目标得分/人才观得分/排序/绩效结果/员工自评/部门评语"），**数据从 R4 开始**。源 sheet 可能一层表头（数据 R2 起）或三层（数据 R4 起）——**每次实读 `ws.max_row`、打印 R1-R3 表头、确认数据起始行**，别凭上次结论。
2. **匹配键只能是姓名**：Sheet2 的工号列常是"南通""宿迁"这类区域名而非工号，联合键失效 → 按姓名建 `name2row` 索引（数据 R4 起遍历）。
3. **两种写入模式，先问清或按用户措辞判断**：
   - **增量模式**（用户说"放到/填到"）：只写源 sheet 有值的列，Sheet2 原有内容保留。
   - **覆盖模式**（用户说"以 sheetX 为准 / 直接覆盖"）：K-P 全部列**无条件写入**，源为 None 也写入（= 清空 Sheet2 对应列）。本会话实例：Sheet2 P 列残留了与自评重复的旧文本，用户明确"以 sheet1 为准直接覆盖"后清掉了。
4. **改前备份** `_备份_<标签>.xlsx`，写入后 data_only 重读抽查 K-P 列验证。
5. **验证更新到底改了什么**：对比 `.bak`（操作前）看不出增量变化（都是 None→值）；要对比**上一次操作后的备份**（如 `.bak2`/`.bak4`）才能精确列出"本次实际变了谁"。
6. **备份文件对比前先复制成 .xlsx**：openpyxl 不认 `.bak` 后缀（`InvalidFileException: openpyxl does not support .bak file format`），对比脚本里先 `shutil.copy(bak, '/tmp/xxx.xlsx')` 再 load。
7. **任务完成后清理备份（用户可能要求）**：多次合并/覆盖操作会累积 `.bak`、`.bak2`…`.bakN`，用户确认结果后常会说\"备份都清理下\"。清理前先 `ls -la` 列出目录，**只删自己生成的 `.bak*` 和 Excel 临时锁定文件（`.~文件名`，前缀 `.~`，openpyxl/WPS 残留），绝不动用户的原始文件**（如 `_备份.xlsx`、`-IE.xlsx`、`-配置开发部.xlsx` 这类用户自己的分表）。删完 `ls -la` 展示剩余文件说明各自是什么。

### 多部门页签都在同一主文件（每页签=全员名单，2026-08 实例：Sheet1 汇总 + DE + IE）

场景：一个 .xlsx 里 汇总Sheet1（全员名单、绩效区全空）+ 多个部门页签（DE/IE，**每个页签都含全员名单**，各页签只给自己部门的人评了分）。要求"把 DE/IE 的考核数据按人合进 Sheet1"。这是跨工作簿/单页签合并的变体，多了两个致命坑：**脏列**与**归属判定**（本会话首版脚本曾把 IE 页签错位残留写入 Sheet1 覆盖正确值，靠回读抽查才发现）。

1. **归属判定用"权威值列"，不信行位置/页签名**：页签虽是全员名单，但有值的人才是该部门考核对象。先实读各页签：哪些列有值、哪些是公式。实例判定：DE 归属 = DE 页签 K(得分)或 N(绩效结果)有真实值；IE 归属 = IE 页签 K 列有真实值（#N/A 缓存/空不算）。部长/其他部门/未评新人 在任何页签都无值 → 留空并给原因（部长不评/他部门另评/新人未评），别当漏人报。
2. **同一人可能在两个源页签都有值 → 禁止"非空并集"**：页签若含脏列（见下），并集会拿脏值覆盖另一页签的正确值（实例：IE 页签 P 列脏文本覆盖了 DE 页签正确的部门评语）。正确做法：先判该人归属（只属于一个部门），再从那个部门的页签取值。
3. **脏列识别与处理**：抽查源页签"非本部门行"的目标列——若残留他人文本（实例：IE 页签 P 列=部门评语，朱林/杨嘉阳/顾睿 等非 IE 行上残留了 IE 人的员工自评文本），则该页签该列**整体不可信**：合并时跳过该列（IE 只取 K-O，不取 P），汇报时说明原因，并提示源文件里该列哪些行看似正常（如前几行）由用户自行判断补。
4. **读公式列必须 data_only=True**：页签内公式列（VLOOKUP）对无匹配行缓存 #N/A；不带 data_only 读会拿到公式字符串当"有值"，带 data_only 时 #N/A/None 一律不算有值。**数"有值人数"前先定义可信列集**（如只看 K），别把 K-P 任一非空当有值——脏列残留会被数进去（本会话 IE 误计 37 vs 实 21 的根因）。
5. **按姓名 key 匹配，行序不可靠**：各页签行序可能不同（同名次不同人），必须 norm 姓名（去括号后缀："李光耀（工厂）"→"李光耀"）后建索引，绝不按行号对齐。
6. **写后验证 + 汇报**：回读 Sheet1，**专门抽查此前被脏值污染过的行**确认已修正；按部门报告已填/留空人数（实例：DE55 + IE21 = 76）；留空名单逐人给原因。

## 报价单/方案 → 分项预算表模板填充（政务/项目申报）

用户给 (a) 定稿的 Word 报价单或项目申报方案 + (b) Excel 模板（典型两 sheet：功能点法 / 工作量法），要求"把 N 大系统拆成明细按模板填进 Excel"。**交付物是填好的 .xlsx 文件本身**，不是清单或建议；产出落 `99-软件工厂/98 hermes`，文件名带 `_已填充_<YYYYMMDD>`。

1. **先读模板列头再动笔**：打印 `wb.sheetnames`、每表 dimensions/max_row、表头行、合并单元格；列头逐字抄下作正确性判据。**不新建 sheet、不改模板布局**，只填明细行。
2. **源 docx 先 dump 成可 grep 的落盘文本**：写 `/tmp/docx_dump.py`，按 `行号 | P{段落号} | style | 文本` 输出段落，表格行输出为 `T{表号}R{行号}: cell || cell`，重定向到 `/tmp/docx_dump.txt`。长文档输出必被截断，落盘后 grep 关键词（各费用名 / 总投资 / 成本指标 / 费率）即可一次回到原话。
3. **先建金额口径表再填**：把源文件所有金额（各系统小计 / 软件开发小计 / 实施服务费分项 / 其他费分项 / 总投资 / 成本指标）列全并标注出处，交叉核对后再填。
4. **拆分基数先跟用户确认，只取"软件开发费"口径**：政务方案里"总投资 / 软件开发费 / 各系统小计"是三个不同的数字。用户要的基数通常是**软件开发费小计**（例：216 万 = 六大子系统 192 + 数据整合与接口开发 18 + 系统集成与部署 6），**不要按总投资推算、也不要沿用上一版数字**；口径不明先问一句，比做完两版被否便宜。
5. **单价必须按功能难度分档，禁止全表一口价**（用户点名要求过）：源方案一般有"工程技术人员月人工费用标准"表，先 grep 出该表原文，**确认人员类别数 × 档位数**（常见 2 类人员 × 普通/初级/中级/高级 = 8 个单价；别假设还有第三类，先核实再定级），逐模块按难度定级取价，人月随难度同步浮动。源文件里的综合基准单价（如 1.92 万元/人月）只是"初/中/高级加权均值"，只作**总额一致性校验值与表底注**，不是逐行单价。
6. **金额是权威值**：模块行金额取源文件口径，人月 / 功能点由金额 ÷ 该行单价反算，绝不用四舍五入后的人月反推金额（会漂）。子系统小计与合计用 Excel 公式（SUM）便于用户当场核；数字不带千分位；表底写 `注1..注N`（单位 / 换算口径 / 系数理由 / 口径差异 / 加权均价与源基准均值的偏差）。
7. **两段独立校验**：① 回读生成文件重算（小计 = 模块累加、合计 = 各小计之和）与源文件口径逐一对齐，**并逐行验"人月 × 单价 = 小计"、单价取值落在源文件级别单价表的档位集合内、加权均价与源文件基准均值对得上**（只核合计会漏掉"单价被写成同一个值"）；② 另写脚本确认 sheet / 表头 / 行列数 / 合计公式未被破坏。长输出重定向到 `/tmp/*.txt` + `wc -l` 再 `read_file` 读回。
8. **口径冲突必须报告，不静默改数**：源文件常见 (i) N 大系统小计里塞了实施费/等保测评，与实施服务费、其他费**重复计列**；(ii) 正文总投资 > 成本指标"控制在××万元以内"。政务申报数字不可编改 → 本表按**纯开发口径**填，差额写进表底注，回复里列出重复项/超限项 + **受影响的联动数字清单**（以该小计为基数的费率、占比、总投资），给 A/B 方案让用户拍板，拍板后再联动改正文。

两法换算约定（逐行单价取自源文件**级别单价表**、按功能难度分档，加权均价须与源文件综合基准均值一致；生产率 8 功能点/人月；复用度系数 1.00；公共平台只计对接量）、**难度分档映射与金额归一分摊公式**、对账清单、布局模板与校验脚本骨架见 `references/quote-to-budget-breakdown.md`。

## 验证脚本模式（长脚本用文件跑，别全塞 execute_code）

- **复杂/多步验证脚本（读两表+匹配+比对）容易在 execute_code 里写崩（截断/占位符/引号问题），**稳定做法：`write_file` 写到 `/tmp/verify_*.py`，再 `terminal` 执行 `cd /tmp && python3 verify_*.py`**，输出干净、可重复。
- **lifecycle_guard 崩溃规避**：某些环境里 `terminal` 命令若含绝对 python 路径（如 `/usr/bin/python3 xxx.py`）或引用脚本文件，Hermes 的 lifecycle_guard 解析时可能崩（`ValueError: embedded null byte`，表现为整条命令被拒）。规避：① 用 `PYTHONPATH= python3 -c "..."` 内联执行（清空 PYTHONPATH 还能避免系统 3.9 误加载 venv 3.11 包导致的 urllib3 崩溃）；② 或先 `echo test` 确认 terminal 恢复再重试。
- 写任何带硬编码列号的脚本前，**先打印一遍表头行确认列含义**（本会话验证脚本曾把 列2工号/列3姓名 写反，幸好合并本身用联合键没受影响；核对脚本标签错了会误导人）。列号从表头推导，不凭记忆。

## 关键技巧与坑

- **删重复行**：`ws.delete_rows(r, 1)` 必须**从大行号往小行号删**，否则行号偏移错删。删完序号列会断号 → 遍历 `enumerate` 重排 1..N。
- **找重复行**：按 (工号, 姓名) 分组 `defaultdict(list)`，len>1 即重复；删除前打印每组每行全部列对比，确认内容一致再删（保留第一行）。
- **填缺失日期**：写入 `datetime.datetime(y,m,d)` 并设 `cell.number_format = "mm-dd-yy"` 与已有单元格一致。已有格式用 `cell.number_format` 查看。
- **跨表按姓名匹配**：Sheet2 常无工号列，只能按姓名。Sheet1 可能同名多行 → 去重映射时优先第一行、入职日期非空的那行。
- **数据完整性**：匹配不到的人**留空并列出**，告诉用户"Sheet1 里没有"，绝不编造入职时间；可建议查企业微信通讯录等权威来源。
- **差异核对**：集合差 `{p["name"] for p in s1} - {p["name"] for p in s2}`，输出姓名+类别+部门+入职/离职，帮用户判断是"漏人"还是"离职/试用期正常不在"。
- **同名跨表状态可能不一致**：同一个人可以同时出现在两张表但状态字段冲突（实例：郭丹仪 Sheet1="在职"/base=苍南，Sheet2="离职"/离职时间 7/30）。核对差异时遇到同名要打印两表各自的状态列对比，别默认一致；向用户点明"不是多出来的人，是状态不一致"。
- **序号最大值 ≠ 实际人数**：用户手动删行后常不重排序号，导致"Sheet1 序号编到 99 但实际只有 91 个数据行"。用户报出的人数可能来自序号列而非真实行数。排查：打印完整序号列表 + `len(有姓名行)`，算断号 `missing = [i for i in range(1,max+1) if i not in seqs]`，并列出每个断号前后是谁（"14号邵叶强 后面直接跳 16号孔雨晴"），一次性给用户看"你看到的数字是序号，实际 N 人，断了 M 个号"。
- **用户说"减掉X人对不上"时的核对算术**：用户常假设去掉某几人就能对齐，但差异集往往比他想的更大。回复模板：先给两表实际人数，再给完整差异集（每人都标 类别/在职/离职 状态），然后**显式演算**："减 4 人 → 97-4=93，还剩 2 个多的（鲁雯婧、王影臣），93 vs 91 仍差 2"；再给完全对齐的方案（删全部 N 人或另一表补 N 人）。别只说结论，把减法算式写出来，用户才信。
- **离职人员判断**：Sheet2 在职名单没有离职者是正常的，不要当漏人报。
- **追加/写入新行**：一律写到**最后一个有数据的行之后**（先扫 max_row 找最后非空行），写入前再次确认目标行全空；若表格中间有空行/用户手动插入过行，千万别按"上一人所在行+1"猜位置——会覆盖中间原有数据。**任何写操作后必须核对总数**（期望值 vs 实际），对不上立刻从备份 diff 出被覆盖的行（`set(备份名单) - set(现名单)`）。
- **复制列结构（含合并表头+样式）**：从备份/其他 sheet 复制一区块（如绩效列）到目标表时，不能只 copy 值。做法：`from copy import copy`；逐单元格 `dst.value = src.value`，且 `if src.has_style:` 复制 `font/border/fill/alignment/number_format`；合并单元格必须重新 `ws.merge_cells("K1:P1")`（openpyxl 复制值不会自动带合并）。验证时 `ws.merged_cells.ranges` 列出合并区核对。
- **追加行保持格式一致**：从模板行（选最后一个数据行或倒数第二行）`copy` 样式到每个新行（font/border/fill/alignment/number_format），新行值与表头结构匹配；序号续接最后一个序号+1。
- **追加后验证三件套**：① 总人数 = 旧人数 + 追加数；② 序号从 1 到 max 连续无缺号（`missing = [i for i in range(1,max+1) if i not in seqs]`）；③ 姓名去重检查——追加前先确认没有把已有的人重复补进去。
- **删除整表**：数据迁完、用户确认以某表为准后，`del wb["sheet名"]` 即可，`wb.sheetnames` 验证。
- **用户可能手动改文件（甚至重构整个工作簿）**：用户常在对话间隙自己开 Excel 手动调整（加人/删行/改状态），且可能把表结构整个对调（哪张表是主表、表头列序、数据起始行都会变——本会话就出现过 Sheet1 恢复、Sheet2 变为考评表、数据起始行从 2 变 4 的情况）。动手前重新 `load_workbook` 读当前状态：打印 `wb.sheetnames`、每张表 max_row/max_column、表头行、数据起始行，别依赖上次分析结论或参考文件里的旧结构；用户手动调整过的内容以当前文件为准。
