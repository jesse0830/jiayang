# Directory Curation（目录清理与重组）

用于用户说“这个目录太多了，帮我清理一下”“整理一下这个文件夹”“东西太乱了”，或某个交付目录顶层条目已经失控。目标是**顶层条目数降下来、结构可预期、任何一步都能回滚**，不是把文件删掉。

和 `document-corpus-audit` 的区别：那个是“读懂这批文档”（出分析报告 + 索引，不动文件）；这个是“把目录收拾干净”（移动文件，出整理清单）。用户只是要整理时不要交付一份审计报告。

## 铁律（每次都要遵守）

1. **只移动，不删除。** 这些目录里是对外交付物和历史版本，误删不可逆。真正冗余的大文件移进 `~/.Trash/<目录名>_清理_<YYYYMMDD>/`（Finder 可“放回原处”），其余一律进根目录下的 `_归档/`。
2. **先盘点，再动手。** 拿到总大小、顶层条目数、**完整**文件名清单（不是 `head` 一截）、各子目录体积，分类定稿以后才 `mv`。用户说“太多了”首要指标是**顶层条目数**，不只看体积。
3. **每次移动都写清单。** `_归档/整理清单_<YYYYMMDD>.json` 记录 `from → to`，这是唯一的回滚依据；交付时必须主动告诉用户清单路径和回滚方法。
4. **不覆盖同名文件。** 目标已存在就记为冲突报出来，让人判断，不要 `os.replace` 把旧文件盖掉。
5. **盘点与移动分离。** 盘点结果直接决定分类，先只读、后写，不要边看边移。

## 分类四桶

| 桶 | 去向 | 判定 |
|---|---|---|
| 在用成品 | 编号主题目录（如 `01 绩效与人事`、`02 方案与汇报`） | 最新版本、对外交付、还要继续改 |
| 旧版本 | `_归档/旧版本/` | 被新版本取代；其中**结论已被推翻的版本要在 README 写明“禁止对外”** |
| 中间件 / 临时产物 | `_归档/构建中间件/` | 分页稿、raw json、编号映射、构建脚本输出 |
| 真冗余大文件 | 废纸篓 | md5 不同但已被同一成品取代的导出件、重复打包件 |

主题目录命名**沿用父目录既有习惯**（父级是 `01 招聘` / `02 绩效` / `04 汇报`，就用同样的“编号 + 中文名”），不要另起一套风格。目录数控制在 5 个左右，分太细等于没整理。

## 步骤

1. **看环境**：`ls` 父目录拿命名习惯；`git rev-parse --show-toplevel` 判断是否在仓库里（在仓库用 `git mv`，否则 `shutil.move`）。
2. **盘点**：`du -sh .`、`ls -1 | wc -l`、完整清单、`du -sh */`。大文件单独列出，体积通常集中在 1-3 个文件上。
3. **查“别处是否已有真源”**：笔记 / MBA / 学习类内容真源常在 obsidian vault 或另一个仓库，而工作目录里只是副本。**先去看真源有没有更新的版本**，确认是副本就只归档、不删除——不要因为“我这边有更新的”就删掉别处的。
4. **写 plan.json**（见模板），先 `--dry-run` 过一遍看会动哪些文件，再实跑 `scripts/organize_dir.py`。
5. **验证**：`missing` 必须为 0；移动后抽查一个带图/带相对链接的文档，确认还能打开（md 引 `xxx_assets/图.png` 是相对路径，**md 与 assets 目录必须一起移进同一个目标目录**，否则图片全断）。
6. **写根目录 README**：`README_目录说明_v1.0.md` —— 一行说明整理规则 + 目录树（每个目录一句话说明装什么、关键文件叫什么）+ 本次前后对比表 + 废纸篓里放了什么 + 回滚方式。以后每个新文件按这张表归位。

## 交付话术（用户要的是结果，不是过程）

先给前后对比表（顶层条目 97 → 6；占用 105M → 57M），再给“三个关键处理”（哪些归档、哪些进废纸篓、为什么），最后给回滚入口。**不要出现“已完成清理”这种没有数字的结论句。** 数字不带千分位。

结尾可以给一个可选的进一步动作，并带上数字（“02 目录顶层 20 项，要不要把九江大文件再收进子目录降到 16 项”），不要泛泛问“还需要我做什么”。

## 坑

- **移进废纸篓不释放磁盘**。报告里写“目录占用从 105M 降到 57M”，并说清“清空废纸篓后释放 48M”，不要写“已释放”。
- **`_归档` 只套一层**：`_归档/旧版本/`、`_归档/构建中间件/`，不要 `_归档/2026/10/版本/` 这种深路径，找东西反而更难。
- **manifest 是唯一回滚依据**：不要用 `rm` 清理，也不要只在对话里说“我移好了”。用户过两周问“那份旧稿在哪”，靠 manifest 一条命令就能还原。
- **归档不等于销毁**：被取代的 v1.0 留在 `_归档/旧版本/` 并在 README 标“禁止对外”，比删掉更安全——内部复盘还要用。
- **别顺手重排父目录**：只动用户点名的那个目录，父目录结构是别人的约定。

## 支持文件

- `scripts/organize_dir.py` —— 按 plan.json 执行移动、写回滚清单、打印未命中项与剩余顶层条目；支持 `--dry-run`。
- `templates/plan.example.json` —— plan 的写法示例（主题目录 / 归档 / `__TRASH__`）。
