# Enterprise Revenue Data Analysis (企业收入数据多维分析)

适用于对部门/公司的收入数据进行结构化多维分析，输出可视化洞察报告。

## 数据源特征

通常来自 Excel 文件，结构如下（SmarDaten OA 导出或手工整理）：

| 列 | 说明 | 类型 |
|----|------|------|
| 项目编号 | P2025XXXX | 文本 |
| 项目名称 | 中文项目名 | 文本 |
| 合同编号 | SA-03-XXXX | 文本 |
| 里程碑 | 首付款/初验款/终验款/质保款等 | 分类 |
| 客户 | 客户全称 | 文本 |
| 项目（长名） | 详细项目名+合同方 | 文本 |
| 所属部门 | 深圳代表处/南京代表处等 | 分类 |
| 责任人 | 项目负责人 | 文本 |
| 收入金额 | 数字 | 数值 |
| 收入日期 | YYYY-MM-DD | 日期 |
| 收入备注 | 验收信息/回款说明 | 文本 |

## 标准分析维度（9维）

### 1. 全量汇总

```python
total_revenue = sum(r[8] for r in rows if r[8] and isinstance(r[8], (int, float)))
print(f"全年总收入: {total_revenue:,.2f}")
```

对照公司目标（如7200万），计算完成率。

### 2. 月度趋势

- 按 `收入日期[:7]` 聚合（月粒度）
- 输出：金额、笔数、占比
- 识别淡旺季（如 SmarDaten 典型：5-9月低谷，12月冲刺）

### 3. 里程碑结构

- 按里程碑类型聚合金额
- 标注"终验款/验收款/上线款"为高质量回款
- "质保款"为后期运维（利润率高但金额小）
- "其他"大类通常占比较高（25-35%）→ 需排查分类是否规范

### 4. 部门收入排行

- 输出：收入、笔数、单笔均值
- 单笔均值反映项目质量（高 = 大项目，低 = 项目小而散）
- 极低值标注（如某部门全年仅7500元→建议关闭或合并）

### 5. 责任人TOP

- 个人收入排名
- 注意"未分配"行可能导致排名偏差 → 需要排查

### 6. 大客户集中度

- 统计客户数量
- 计算前5/10/20客户占总收入百分比
- <35% = 分散健康 / 35-50% = 中等集中 / >50% = 依赖风险高
- 列出每个大客户的收入贡献

### 7. 项目维度

- 按项目名聚合
- 合并同一项目不同里程碑的收入
- 识别最大的几个项目盘子

### 8. 单笔收入区间分布

| 区间 | 典型特征 |
|------|---------|
| <5万 | 质保款/维保/小增补 — 占比低但笔数多 |
| 5-20万 | 常规项目里程碑 — 中坚力量 |
| 20-50万 | 大项目里程碑 — 效益高 |
| 50万+ | 头部项目 — 占比最高但数量极少 |

### 9. 里程碑排除分析（有效产能）

用于计算"不需要人力投入"或"低人力投入"的收入占总收入比例，从而得出**有效产能收入**和**真实人效**。

**排除规则：**

| 里程碑/备注 | 排除 | 原因 |
|-------------|:----:|------|
| 首付款 | ❌ 排除 | 签约即收，无人力投入 |
| 质保款 / 质保款1 | ❌ 排除 | 验收后收取，低人力投入 |
| 空里程碑+备注含"首付""预付" | ❌ 排除 | 同首付款 |
| 空里程碑+备注含"质保""维保" | ❌ 排除 | 同质保款 |
| 空里程碑+备注含"验收""终验""初验""上线" | ✅ 保留 | 正常生产 |
| 终验款/初验款/验收款/上线款 | ✅ 保留 | 正常生产 |

**计算过程（Python）：**

```python
exclude_keywords = {
    "首付": ["首付", "预付"],
    "质保": ["质保", "维保"]
}

total = sum(r.amount for r in rows)
excluded_milestone = sum(r.amount for r in rows 
    if r.milestone in ["首付款", "质保款", "质保款1"])
excluded_empty = 0
for r in rows:
    if r.milestone == "" and r.note:
        if any(kw in r.note for kw in exclude_keywords["首付"]):
            excluded_empty += r.amount
        elif any(kw in r.note for kw in exclude_keywords["质保"]):
            excluded_empty += r.amount

effective = total - excluded_milestone - excluded_empty
print(f"有效产能: {effective:.2f}万 (排除{total-effective:.2f}万，{((total-effective)/total)*100:.1f}%)")
```

**关键发现模式：** 排除后有效收入通常比总收入低10-20%，意味着真实人效比表面人效低相近比例，扩招需求相应扩大。

## 交叉分析（录音+数据）

当用户同时提供录音反馈时，将"听见的"与"算出的"交叉验证：

| 录音要点 | 数据验证 | 信号 |
|---------|---------|------|
| "目标7200万" | 实际3185万(44.2%) | 缺口大，需下半年加力 |
| "成都低效" | 全年仅7500元 | 建议关闭/合并 |
| "12月压线" | 12月占19.4% | 回款风险集中 |
| "团队人效低" | 184笔/15部门 ≈ 12笔/部门 | 看人均，不是总笔数 |

## 输出格式

分析结果用结构化文本呈现，数据优先于叙述。报告结构：

```
一、总量概览（总收入 + 完成率）
二、月度趋势（表格 + 关键发现）
三、部门排行（表格 + 两极分化标注）
四、大客户集中度（表格 + 风险判断）
五、milestone 回款质量（表格 + 问题标注）
六、关键问题总结（结论列表）
```

## Python 实现要点

- 使用 `openpyxl` 直接读取，`data_only=True` 获取计算结果而非公式
- `read_only=True` 节省内存
- 遇到 `'ReadOnlyWorksheet' object has no attribute 'dimensions'` → 去掉 `.dimensions` 调用
- 集群统计用 `defaultdict(float)` + `defaultdict(int)`
- 排序用 `sorted(dict.items(), key=lambda x: -x[1])`

## 典型陷阱

- Excel 文件名含中文字符 → 用终端传参，没问题
- 收入金额可能为 None → 加 `if r[8] and isinstance(r[8], (int, float))` 过滤
- 日期可能同时有 `datetime` 和 `str` 两种类型 → 统一 `str(r[9])[:7]`
- 责任人、客户名可能为空 → 标记为'未分配'/'未知'
- 同一项目分多次回款（多个里程碑行）→ 项目维度聚合时自动合并
