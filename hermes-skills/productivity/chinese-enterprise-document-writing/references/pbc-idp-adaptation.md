# PBC (绩效承诺书) Excel 模板 — IDP 部分补充与编辑

适用于用户收到公司 HR 下发的 `.xlsx` 格式的 PBC 模板（企业干部绩效承诺书），需要补充第三部分的 IDP（个人发展计划 Individual Development Plan）。

## 模板结构

典型的 SmarDaten 企业干部 PBC Excel 文件结构：

| 列 | 内容 |
|----|------|
| A 列 | 序号（如 1.1, 1.2, 2.1） |
| B 列 | 维度（绩效目标 / 核心价值观 / 个人发展计划 IDP） |
| C 列 | 目标描述（需要用户填写的内容） |

## 三大核心部分

1. **第一部分：绩效目标（1.1 关键业务目标 + 1.2 管理增效目标）** — 这是用户最核心的部分，通常需要结合公司年度目标和部门规划来填写
2. **第二部分：核心价值观践行** — 标准维度，每项写一条具体行动
3. **第三部分：IDP（个人发展计划）** — 通常为空或只有占位的序号行(1和2)，需要用户自主填写

## IDP 内容设计方法论

### 参考他人的 IDP 结构（从图片 OCR 提取）

当用户有其他人的 IDP 截图（如 HR 总监的 IDP），可以 OCR 提取其结构并做岗位适配：

```
# 示例：提取 HR 总监的 IDP 结构后
HR 的 IDP:
1. 干部梯队搭建能力（含25人M2/M3一对一沟通 + 腰部人员亮相 + 总裁赋能）
2. AI应用与数智化能力（含HR系统业务架构 + 公司产品实践 + AI在HR应用）

→ 适配为软件工厂负责人的 IDP:
1. 交付体系标准化与规模化复制能力
   (对齐: HR的"梯队搭建"→ 对应工厂的"交付能力复制")
2. AI Agent 赋能交付能力
   (对齐: HR的"AI应用"→ 对应工厂的"AI在交付中的应用")
```

### IDP 适配原则

| 来源者角色 | 用户角色 | 适配方向 |
|-----------|---------|---------|
| HR 总监 | 软件工厂负责人 | 用人能力 → 建交付体系能力 |
| 技术总监 | 软件工厂负责人 | 技术深度 → 技术管理+标准化 |
| 销售总监 | 软件工厂负责人 | 市场开拓 → 交付效率提升 |

### 拆解方法

把对方的 IDP 每项拆出**能力维度**（what）和**落地动作**（how），再映射到自己的角色：

```
对方原文: "干部梯队搭建能力（25人M2/M3一对一沟通+腰部人员亮相+总裁赋能）"
  ├── 能力维度: 人才梯队建设
  ├── 落地动作: 1:1沟通 / 识别腰部 / 高层赋能
  └── 适配到工厂负责人:
      能力维度一致（团队建设），落地动作改为:
      PM:AE 结对机制 → 定制化培养路径 → 项目实战锻炼
```

## Excel 写入限制

**通过 Hermes 工具链无法直接将内容写入 `.xlsx` 文件。** 原因：

1. **terminal 工具**: 用户环境拒绝了通过 terminal 执行写入脚本的操作 (BLOCKED: User denied)
2. **execute_code**: 能运行 Python 代码（含 openpyxl）但无法导入所需库（可能在特定 sandbox 中）
3. **patch**: 不支持二进制文件

**推荐流程（已验证可行）：**

```
1. 用 execute_code 或 terminal（如可用）读取 xlsx 内容 → 了解现有数据
2. 设计 IDP 内容 → 与用户多轮迭代直到定稿
3. 将最终IDP内容写入桌面 `.md` 文件（如 `PBC_IDP_补充内容.md`）
4. 用户手动打开md文件，复制内容粘贴到 xlsx 对应位置
   - 建议用 markdown 表格格式输出，方便用户直接复制
   - 保存路径：`/Users/jesseyoung/Desktop/PBC_IDP_补充内容.md`
```

**这个流程已经过用户验证并接受。** 不要尝试用 terminal 或 execute_code 写入 .xlsx 文件——用户环境的安全策略会拦截终端写入操作。写 md 到桌面让用户自己粘贴是最快路径。

### IDP 内容在 md 文件中的最佳呈现格式

经用户验证的格式——用 markdown 表格直接输出，序号列清晰对应 PBC Excel 中的行号：

```markdown
| 序号 | 发展维度 | 具体内容 |
|:---:|:--------|:---------|
| 1 | 团队效能管理与人才梯队建设能力 | 落地动作：... |
| 2 | 面向客户中高层的产品价值传达与方案汇报能力 | 落地动作：... |
| 上级支持项 | — | 需要上级提供的支持... |
```

注意：
- 上级支持项不需要序号，单独一行
- 每条 IDP 描述要包含可量化的落地动作（括号内说明）
- IDP 内容不应与 PBC 第一部分（业务目标）重复——用户会明确指出来

## IDP 内容迭代模式：角色定位驱动法

**重要发现：用户会通过多次迭代逐步逼近理想的IDP内容，每次迭代都更精准地贴合其岗位角色。**

### ⚠️ 用户纠正记录：IDP ≠ 业务目标

当写第一版IDP（"交付体系标准化与规模化复制能力"）时，用户反馈"偏最早一版写的业务目标"。

**纠正要点**：
- IDP不是PBC第一部分（业务目标）的变体 — 用户能立刻识别出"这写的是业务目标不是发展计划"
- 区分方式：业务目标回答"我要完成什么任务"，IDP回答"我要成为什么样的管理者/提升什么能力"
- 措辞体现：IDP要用"培养XX能力/提升XX能力/建立XX机制"而非"完成XX项目/实现XX收入"

### ⚠️ 用户纠正记录：角色定位驱动而非话题驱动

当写第二版IDP（"AI赋能软件工厂研发效能提升"）时，用户反馈"需要从对接客户中高层的角度去写"。

**纠正要点**：
- IDP方向取决于用户的核心角色缺陷（作为工厂厂长，短板是见客户讲价值，不是当技术带头人）
- 不要从热门话题入手（AI/数字化等），要从用户当前岗位的**角色差距**入手
- 每个管理岗的IDP都有天然的双维度：对内（管团队/建体系）+ 对外（接客户/讲价值）

迭代模式示例（软件工厂厂长，从通用到精准）：

```
Round 1: 交付体系标准化与规模化复制能力
  → 用户反馈:"偏最早一版写的业务目标"
  → 问题: 把PBC第一部分(业务目标)的内容写进了IDP(发展计划)
  
Round 2: AI赋能软件工厂研发效能提升的能力
  → 用户反馈:"需要从对接客户中高层的角度去写"
  → 问题: 纯内部效率，缺少外部视角

Round 3: 面向客户中高层的产品价值传达与方案汇报能力 (序号2)
  → 用户认可（方向对了）
  
Round 4: 团队效能管理与人才梯队建设能力 (序号1)
  → 核心框架：量化效能Dashboard + 超级个体标杆 + DE人才双通道
  → 用户认可，定稿
```

### 核心迭代原则

1. **IDP ≠ 业务目标/绩效考核** — IDP是个人的能力短板和发展方向，不是PBC第一部分业务目标的变体。如果第一条看起来像"我们要完成XX任务"，那就是走偏了。
2. **岗位角色的双维度框架** — 软件工厂厂长（或其他管理岗）的IDP天然有两个维度：
   - **对内**：管团队、建体系、提效率
   - **对外**：接客户、讲价值、拓视野
   两方面兼顾才完整。只写对内或只写对外，用户会觉得"少了什么"。
3. **从"我做什么"到"我成为什么"** — 业务目标回答"我要做什么事"，IDP回答"我要成为什么样的管理者"。措辞上要体现能力成长（培养XX的能力/提升XX的能力/建立XX的能力）而非任务达成（完成XX项目/实现XX收入）。
4. **上级支持项要与IDP匹配** — 不需要支持通用的东西，而是要写清楚"我需要上级做什么才能让我练成这个能力"。比如练客户沟通→需要方总陪我去做模拟演练。

### 软件工厂厂长IDP典型框架

当用户角色为软件工厂厂长/交付负责人时，经过迭代验证的典型IDP框架：

| 维度 | 能力项 | 核心落地动作 |
|------|--------|-------------|
| 对内（管团队） | 团队效能管理与人才梯队建设 | ①量化效能Dashboard ②超级个体标杆③DE双通道（横向→PM/AE，纵向→架构师） |
| 对外（接客户） | 面向客户中高层的产品价值传达与方案汇报 | ①电梯演讲 ②案例包提炼 ③主导2次汇报 |

支撑系统：
- 数据驱动：建立量化指标体系，用Dashboard做管理决策
- 人才机制：建立"造血-输血"循环，Q3至少2人转岗/晋升

## IDP 内容的风格要求

- **每条 IDP 包含两部分**：能力维度（标题）+ 具体落地动作（括号内说明）
- **长度**：每条 20-40 字，简洁清晰
- **可衡量**：每条 IDP 要有具体的可量化/可验证的动作，如"完成XX人培训"、"搭建XX机制"
- **与岗位强相关**：软件工厂负责人的 IDP 应聚焦交付效率、团队培养、AI赋能，而非泛泛的"沟通能力提升"
- **直接可读**：不需要前置解释，领导一看就明白 "哦，他要练这个能力"

## 常见 PBC Excel 内的数据读取

```python
from openpyxl import load_workbook

wb = load_workbook(path, data_only=True)  # data_only=True 获取值而非公式
ws = wb.active

for row in ws.iter_rows(min_row=1, max_row=ws.max_row, max_col=ws.max_column, values_only=False):
    cells = [cell.value for cell in row]
    print(cells)
```

注意：`ws.max_row` 只能获取有数据的行数，合并单元格可能产生间隙。
