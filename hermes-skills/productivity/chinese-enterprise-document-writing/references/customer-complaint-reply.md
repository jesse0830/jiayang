# 客户投诉/问题函复（整改方案 + 应急机制复函）

客户正式来函投诉系统问题频发，要求限期（如 10 个工作日）内给出**解决方案与应急机制**，并明确要求：
找根因、从产品/研发层面根本解决、**不止依赖驻场运维**、避免问题复现。运维/驻场先写一版方案，用户觉得不完善，要求优化成能正式发客户的复函。

## 核心方法论：把客户的诉求逐条映射到复函结构

客户函件是"考题"，答复必须逐条接住。先列客户诉求，再检查草稿缺什么：

| 客户诉求（典型原文） | 复函必须有的对应节 |
|---|---|
| "根据问题复现找根因" | 二、根因分析（分模块，每类给 2-3 个根因维度） |
| "从产品、研发等根本解决" | 三（三）产品与研发层面根本性改进（重构/抽象化/自动化校验，明确"不依赖驻场单点"） |
| "不止依赖驻场运维" | 五、组织保障（三层支持体系表：一线驻场/二线研发/三线产品架构） |
| "避免问题复现" | 三（一）已解决问题的防复发加固（回归测试/统一基线/缺陷档案） |
| "给予解决方案与应急机制" | 三、整改措施 + 四、应急响应机制（分级 SLA 表） |
| "10 个工作日内" | 六、整改时间表（第3/5/10/30个工作日节点表） |

草稿通病：根因分析写得好，但"解决方案"只有一句"已全部解决"——没有防复发、没有研发层整改、没有应急分级、没有组织保障、没有时间表、没有正式函格式。**先列诉求映射表，缺口一目了然。**

## 标准复函结构（7 节 + 首尾）

1. 称谓 + 收悉语 + 重视表态（成立专项整改小组）
2. 一、问题整体情况（总数/分类/处理状态，如"考勤21项+绩效28项+其他4项=53项，已解决X项"）
3. 二、根因分析（分模块：考勤/绩效/其他，每类现象→根因，避免只堆现象）
4. 三、整改措施
   - （一）已解决问题防复发加固：回归测试、升基线、缺陷档案
   - （二）专项排查中问题：给**明确时限**（预计【N】个工作日内）+ 修复前人工兜底（2小时介入恢复）
   - （三）产品与研发层面根本性改进：模块重构、配置化改造、自动校验任务
5. 四、应急响应机制：问题分级表（P1阻塞/P2严重/P3一般/P4建议：判定标准/响应时限/解决时限）+ 响应流程 + 例行巡检（周/月/季度）
6. 五、组织保障：三层支持体系表（一线驻场/二线研发/三线产品架构），强调"驻场是一线，不是唯一"
7. 六、整改时间表：第3/5/10/30个工作日节点表
8. 七、结语：承认不足（版本管理/配置治理/质量保障）+ 致歉 + 承诺接受监督
9. "特此函复" + 落款（公司全称 + 日期）

## 易错点/注意

- **数据不猜**：次数/比例用原稿数字，不确定的用【】占位让用户填；客户全称若函件无抬头，用"XXX（以下简称'历下城发'）"并提醒用户核实
- **内部技术黑话要转化**：如"分支版本太老""硬编码在服务编排"→ 面向客户表述为"版本基线未同步升级""关联逻辑固化在配置中"，保留专业度但客户能懂
- **"待复现后解决"是雷**：客户最反感。改为"已建立复现监控 + 调取日志回溯分析 + 预计【N】工作日定位 + 修复前人工兜底"
- **承诺要标【待确认】**：SLA 时限、资源（驻场1名、7×12小时、研发24小时待命）必须标注需团队确认可兑现，别替团队拍板
- 落款日期留空（"2026年8月　日"）由用户填

## docx_create.py 生成坑（本类复函必踩）

用 `docx` skill 的 `scripts/docx_create.py spec.json out.docx` 生成中文正式函：

1. **styles 是 LIST 不是 dict**：`"styles": [{"name": "...", "base": "Normal", "font": "仿宋", "size_pt": 12, "bold": true, "color": "000000"}]`
   - 字段名是 `size_pt`（不是 `size`）；颜色是 hex 字符串无 `#`
2. **page 边距用 `margins_mm`**：`"page": {"width_mm": 210, "height_mm": 297, "margins_mm": {"top": 25, ...}}`
   - 不是 `margin_top_mm` 这种平铺字段
3. **内置样式名冲突**：`Title`/`Heading 1`/`Normal` 等 python-docx 默认已存在，`add_style` 会 ValueError。自定义样式名用 `DocTitle`/`H1`/`H2`/`Body`
4. **heading 块不支持自定义样式**：`{"type": "heading"}` 走内置样式；要自定义字体排版就全部用 `{"type": "paragraph", "style": "H1", "text": "..."}`
5. 表格用 `{"type": "table", "header": [...], "rows": [[...]], "style": "Table Grid"}`（header 默认加粗）
6. 生成后验证：`docx_validate.py` + `read_file` 读回抽查开头段落
7. `footer_page_numbers: true` 顶层字段可加页码
