# 汇报话术 / 高层汇报材料（演讲逐字稿）工作流

给客户高层或内部高管做方案汇报前，生成"照着能讲"的逐字稿话术。适用于：客户方案汇报（Agent/数智底座/数字化方案）、月度/季度工作汇报、立项汇报等。

## 触发场景
- 用户说"明天要给XX高层汇报，帮我搞一套话术"
- 用户给了 PPT（.pptx）+ 飞书妙记/录音链接，要求结合两者生成话术
- 汇报时间紧（"他在喝酒，让我去"—— 替领导/同事代讲）

## 标准流程

### 1. 素材采集（并行）
- **PPT**：用 python-pptx 提取全部 slide 文字（含分组 shape 递归、表格）。见 powerpoint skill。30页级 deck 直接全文提取，不要只看标题。
- **飞书妙记（minutes）**：`browser_navigate` 打开链接 → 页面有"智能纪要"（章节纪要 + AI 总结）→ 用 `browser_console` 读 `document.body.innerText` 分段提取。**妙记的"章节纪要"就是黄金素材**——每段有标题+总结，直接对应 PPT 汇报节奏。
  - 妙记要点：标题=该段主题，正文=该段核心逻辑；页面底部"文字记录"是逐字稿（可引用原话风格）
  - 场景可能不同（如给成都城投的录音→给苍南中广核汇报）：**汇报框架通用**，把客户名/场景名做通用化处理，试点场景留给现场互动

### 1.5 售前话术素材（单页话术润色整合）
- 售前可能发来"某页 PPT 的话术"（一段文字），要求整合进汇报稿：**保留全部核心论点，只做口语化处理**（强调关键词如"Agent/一人办"、分点节奏、补过渡句），让用户照着念流畅
- 售前话术往往含拔高论点（如"人的价值不降反升——信息更多，决策/管理更精细"），这类打动高层的金句必须保留并放在该页核心位置
- 整合后要提示：话术里的品牌概念（如"一人办"）如果客户没听过，自然带过即可，不用展开解释

### 2. 话术结构（客户高层汇报通用骨架）
完整版（25-30min）七段：
1. 开场（1-2min）：讲清"三件事"——为什么建、建成什么样、怎么落地
2. 建设背景/必要性（3-4min）：三个压力 → 为什么必须统一建设
3. 建设目标（3min）：对内提效 + 对外商业化 双维度
4. 核心能力（8-10min）：按方案模块讲，每模块"一句话定义 + 价值点"
5. 落地路径（3-4min）：步骤化流程，强调"业务方不参与开发"
6. 商业化/合作模式（4-5min）：三大保障 + 客户最关心的（知识产权归客户、轻量合作、按需PO）
7. 收尾（1-2min）：总结三件事 + 下一步建议（先做1-2个场景试点）

**必须附精简版**（12-15min）：每段压缩成 1-2 行要点，时间紧时直接用。

### 3. 用户偏好（已确认）
- **生成 Word 文档**（.docx）供 iPad/WPS 打开照讲；**电脑开 PPT 翻页**，话术段落标题里标注"对应PPT X-Y页"
- 不用生成新 PPT（用户自己用现成 PPT）
- 话术用 markdown 源稿 + python-docx 转 Word 双份交付，存到用户工作目录（如 98 hermes/）

### 4. 交付格式
- Word：A4、微软雅黑、标题分级配色（H1深蓝18pt/H2蓝15pt/H3黑13pt）、分隔线分节、关键句加粗
- 转换脚本：`templates/md2docx_cn.py`（markdown → 带格式 docx，中文处理，A4+微软雅黑+标题配色）——`PYTHONPATH= python3 md2docx_cn.py in.md out.docx`
- 生成后验证：`read_file` 读 docx（自动提取文本）抽查开头/结尾段落，确认无乱码/内容完整
- 附"汇报注意事项"：口吻（面向高层讲价值不讲技术细节）、客户可能关心的点（数据安全/成本/知识产权/周期）、互动技巧（问"哪个业务场景最痛"引导参与）

## 版本迭代（售前多次给新版 PPT）

用户会反复收到新版 PPT（"售前发了最新版"、"我调整了顺序"），必须：
- **每次重新读取 pptx 全文**，不能假设和上一版相同——页数、章节都可能变（实例：42页→51页，新增"AI智能规划"和"商业化保障"两大节；随后知识中心从第18页提前到第11页）
- 对比新旧版差异，更新话术里的页号对应关系；文件名加版本后缀（_v2），旧版保留作参考
- 汇报重心可能整体改变（如从"已建成系统"转向"AI能力+商业化"）——话术重点段落要跟着挪（★标注新的核心部分）

## 坑
- 妙记页面是 canvas 渲染，accessibility snapshot 抓不到正文 → 必须用 browser_console 读 innerText
- 妙记智能纪要有"章节纪要"列表（带时间戳），比 AI 总结更细，优先用
- PPT 里的数字（80%、1-3人月、0.5小时→2分钟）是话术说服力的关键，必须保留并强调
- 汇报对象换了（成都城投→苍南中广核），不要生硬替换客户名——把方案逻辑通用化，试点场景留给现场确认
- **客户定制版 PPT 优先**：如果客户给了专门定制的 deck（如"苍南核电数智化建设新范式"42页），话术必须完全按定制版写——直接引用客户真实落地系统（苍核通/承包商/DER等）、对齐客户战略理念（"三个围绕"）、突出已建成效。通用版 PPT 的话术只作补充素材，不要混用
- **行业专场注意事项**：汇报注意事项按行业定制——核电强调核安全生命线/合规监管/权限审计/数据不出内网；政企强调私有化/信创/知识产权归客户；每次都要点出"已落地的真实系统"（不是 PPT 概念）增强说服力

## 素材源文件解析技巧
- **XMind 源文件（.xmind）**：是 zip 包，解压后读 `content.json`（顶层 list，`[0]['rootTopic']` 为根），递归 `children` 的 `attached`/`detached`/`summary` 三个 key 提取——比 OCR 图片精确 100%（OCR 会漏独立节点）。详见 `references/xmind-parsing.md`
- **PDF**：文本型用 pymupdf；扫描型用 macOS Vision OCR（见 ocr-and-documents skill）
