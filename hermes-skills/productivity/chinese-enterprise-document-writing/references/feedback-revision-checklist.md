# 反馈驱动文档修订检查表（Feedback-Driven Revision Checklist）

当领导/方总对文档给出口头反馈（通常通过会议录音）后，按此清单逐项检查现有文档。

## 通用结构检查

- [ ] **是否有职责定位开篇？** — 上来就写规划/数据？需要先写"为什么做""我的角色是什么"
- [ ] **结构是否金字塔？** — 应该是 定位→背景→现状→策略→量化，而非平铺直叙
- [ ] **各维度是否MECE？** — 各章节内容是否有交叉重叠？
- [ ] **是否有量化成果总表？** — 每条策略对应可量化的验收标准

## 内容深度检查

- [ ] **人效模型** — 写了人员配置，但配比的依据是什么？按城市/类型的基准线在哪里？
- [ ] **落地路径** — 只写了"要做什么"，没写"分几步、什么时候做完"？
- [ ] **协作关系变革** — 只写了内部怎么做，没写与研发/其他部门的协作方式变化？
- [ ] **AI场景** — 有没有结合当前技术趋势（AI提效）？有没有具体落地场景？
- [ ] **风险与瓶颈** — 只写了美好目标，有没有写困难在哪里？卡点是什么？

## 表达方式检查

- [ ] **开头要抓人** — 第一眼就能看出核心价值
- [ ] **用词精准** — 不用模糊词（"加强""优化""提升"后面要跟具体的改变）
- [ ] **数据说话** — 每一条结论都有数据做支撑？还是凭感觉写的？
- [ ] **成果导向** — 领导看的是"你能交什么结果"而不是"你做了什么动作"

## 典型差距与修复方向

| 差距 | 原有写法 | 优化后 |
|------|---------|--------|
| 缺职责 | "团队目前XX人，分布在XX城市…" | "我的职责是搭建一个可复制的交付体系，核心解决三个问题：人效、质量、规模…" |
| 缺人效模型 | "成都要12个人…" | "按城市分级设定人效基准：一线城市30万/人/月，新一线25万，二三线20万。成都按新一线基准，需12人。" |
| 缺量化 | "加强PM和AE的配合…" | "推行PM-AE结对模式，目标：需求到设计周期缩短40%，返工率降低至5%以下。" |
| 缺落地路径 | "建设统一交付中心…" | "Phase 1 (Q3): 南通试点，跑通流程 → Phase 2 (Q4): 南京/成都复制 → Phase 3 (H1): 全国统一标准" |
