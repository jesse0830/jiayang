# 备考/学习材料生产

用户（杨嘉阳）会持续追加这类需求：MBA 管理类联考与英语二的逐日计划、核心词汇、考点归纳、日打卡面板与台账。每次都按同一套流程交付，不要每次重新设计。

## 触发

「帮我列一下/单独列一下/做一个计划/搞个打卡/要详细一些」「跟 X 分开」。关键词：学习计划、备考、词汇、打卡、台账、考点、逐日。

## 交付规格（硬性）

1. **结构 = 数据 + 生成器两步走**。数据写成 scratch 下的 Python 数据文件（如 `eng_vocab_a..e.py`、`mba_days.py`），生成器脚本（`build_*.py`）读数据渲染 MD/HTML。**不要手写产物正文** —— 改内容一律改生成器再重跑，手改的产物下一轮会被覆盖。
2. **版本号**：新建 = v1.0，修订递加 v1.1/v1.2，标在文件名末尾 **和** 文档头，同一次修订不换名只递加。
3. **一套材料必有唯一「主文档」（hub），升版时把它钉死**：hub 写 `type: hub`，正文首行 `> [!important] 这份就是主文档 —— X 只看这一页`，内容 = 全部资料的分组导航表 + 「每天怎么用」三步。用户问「以哪个文档为主」时，答案永远只有这一份。改版本号时必须同步做三件事：**全库批量改写引用指向新版本**、**把 hub 挂进知识库索引**、**让用户三条路都能打开它**。
   **升版的唯一真源是引用 hub 的生成器常量**：材料正文由生成器渲染，hub 文件名通常硬编码在生成器里（`HUB = "X备考总入口_v1.5.md"`）。只改库里的 MD/bookmarks 而不改生成器，**下一次重跑生成器就会把引用打回旧版**。固定顺序：改生成器常量 → 重跑生成器 → 全库批量改写引用 → 追加 `wiki/log.md` → push → `grep -c` 复核产物里的版本号。见 `references/vault-hub-and-versioning.md`。
4. **三处落位**（每次都要全给，不要只放一处）：
   - 主件：`~/Documents/work/jiayang/obsidian-vault/JesseYoung/MBA/`（**知识资料**：公式速查、考点精讲、词库、计划、打卡面板、hub）
   - **练习类产物一律进子目录 `JesseYoung/MBA/练习/`**（成套练习卷、专项题库、每日 30 题；目录入口 = `练习总览_v1.0.md`，改东西时同步它）。Obsidian 的 `[[ ]]` 按文件名解析，挪目录不会断链，但 `raw/sources/` 镜像与 `wiki/log.md` 要跟着走。
   - 副本：同仓库 `raw/sources/`（**新增的 hub 也要拷**；改写引用时跳过它，但镜像要全）
   - 工作副本 + 生成器：`~/Documents/work/smardaten/smardatenCorp/99-软件工厂/98 hermes/`（生成器脚本一并拷进去，便于复现）
5. **入库**：obsidian-vault 分支 master，`git add -A` → commit（中文提交信息写清「做了什么 + 版本号」）→ `git push origin master`；结束用 `git status -sb` 确认与 origin 同步，回执里报 SHA。obsidian-git 每 5 分钟自动 commit+push，因此 `git commit` 报 `nothing to commit, working tree clean` 且同时提示 `ahead of origin/master by 1 commit` = **插件已经替你提交了，这不是失败**：直接 `git push`，若回 `Everything up-to-date` 说明插件连 push 都做了——一律以 `git log --oneline -3` + `git status -sb`（无 ahead/behind）为准，不要重试或重写提交。
6. **科目分开 = 分到打卡层**。用户说「把 X 跟 Y 分开」，意味着不只拆文件：X 要有**独立的打卡面板 + 独立的台账**，与 Y 各占各的进度，互不抵扣额度。

## 知识点 ↔ 真题对应表（考点挂真题）

用户会要求「每个知识点至少搞一两个真题案例，我也就知道知识点怎么对应题目的」。这类产物是把**考点归纳文档**与**历年真题语料**缝成一张表，规则如下（做法细节与数据结构见 `references/knowledge-point-question-mapping.md`）：

1. **一条 = 考点 → 题干 → 判定理由（这题怎么一眼认出是这个考点）→ 解法要点 2–4 条 → 参考答案**。只给考点不给题不算完成。
2. **骨架沿用归纳文档的标题层级**（章 → 节 → 考点），保证「对应表」与已交付归纳文档同构，用户两边能对得上。
3. **无真题覆盖的考点不硬凑真题**：改用「改编案例 + 答案 + 解法要点」（note/q/a/pts），并另设一节列出「结构/清单/计划类条目」，一句话说明为何不挂题（例如必背清单、时间策略、复习计划）。
4. **必附反向索引**（按年份 → 该题考的是哪个考点）。用户是拿它做题后回查用的。
5. **答案字母一律自算复核，源页标注与自算冲突时以自算为准**：换成一道自己验算过的题当示例，或把该题降级为「练习用例」并注明条件文本有截断。绝不照抄可疑答案 —— 这份表是用户的学习依据，错的答案比没有答案更糟。
6. **抓取文本残缺的固定处理**：①选项只抓到字母（`A ｜ B ｜ C ｜ D ｜ E`）时**不输出选项行**；②上标丢失（`a3` = a³、`丨a丨` = \|a\|）在文档头加阅读提示；③条件/题干被截断的题不引用具体条件原文，只保留通用解法。
7. **文档头必须有来源与限制说明**：题干来自哪些年份、选项文本是否完整、答案字母的作用（定位用，以自算为准）。
8. **交付前跑覆盖率自检**：从归纳文档抽二至四级标题（剥掉 read_file 带出的 `N:` 行号前缀）与案例数据的考点名逐一比对，打印缺口清单再补。

## 公式速查 / 公式手册类产物

用户会说「X 相关的计算公式，符合 MBA 考试大纲就行」——要的是**可以背、可以默写、可以自测**的一页纸，不是公式推导讲义。沿用「数据模块 + 生成器 + 独立复核脚本」三件套，正文骨架固定为四段：

1. **速记总表**（8–10 行：公式 | 用途）——上场前 30 秒扫一遍的那种。
2. **分节公式**：定义与判定 → 通项（含两点式/中点式）→ 求和（三种等价写法 + 二次型判据）→ 下标和与中项 → 片段和 → 最值 → 奇偶项和 → 条件充分性判断高频坑。每节写「怎么用」而不只是式子。
3. **默写清单**（10 条左右，`- [ ]` 勾选框）。
4. **5 分钟自测**（5–6 题 + 答案与解法要点表 + 时间红线），并注明「任一题超时回上面对应那一节的公式重默」。

硬性约束：

- **严格按大纲，不超纲**：管理类联考数学只含算术/代数/几何/数据分析；数列部分不写递推构造、高阶求和技巧、极限级数。
- **文档头声明「自编整理稿，非真题原文」+ 大纲范围**，源页/真题一律不冒充。
- **自测题答案与题目数据分开，用换算法的独立脚本复核**（暴力枚举、`fractions.Fraction`、差分法等），全过才交付；复核结果写进回执（「6/6 通过」）。
- 公式手册要与练习卷**互相挂链**：同一考点的练习卷题号写进 hub 资料地图或本页脚注，用户才能「背完公式立刻做题」。
- 交付形态默认 MD 落三处即可；用户没明确要 HTML/pptx 就不要造（见 memory 中的 PPT 偏好）。

## 每日 N 题日更系列（每天一套，答案统一在最后一页）

用户口径（逐字）：「我计划每天做 30 道 MBA 综合管理的数学类题目，将答案统一放在最后一页，按照日期生成文件名，尽量真题和模拟题搭配，我每天会让你生成 30 道题。」——所以这是**常驻日更**，不是一次性产物。

固定规格（每天重复，别再问）：

1. **单文件、答案在最后一页**：不拆「试卷版 / 解析版」两文件；顺序固定为 使用说明 → 考点分布 → 第 1 部分 答题卡 → 第 2 部分 问题求解 → 第 3 部分 条件充分性判断 → 第 4 部分 答案（速查表 + 逐题解法要点 + 错题诊断表）。答题卡排在题目前面，答案页用 `---` 隔开。
2. **文件名带日期**：`MBA数学每日30题_YYYYMMDD_v1.0.md`（同日重做递加 v1.1）。
3. **题量与配比**：30 题 = 问题求解 20（第 1—20 题）+ 条件充分性判断 10（第 21—30 题）；覆盖算术/代数/几何/数据分析四模块（各 6—11 题），难度标易/中/难。
4. **真题与模拟搭配**：全卷约 6:4 标 🟦真题改编 / 🟨仿真（目标 18 + 12），每题标 `来源·考点·难度`。真题改编按公开真题的考点与数据改写，**文档头必须声明「非逐字原文，需逐字原题请对照官方真题册」**。
5. **答案分布不许聚堆**：选项次序打乱，使 A—E 各 **6 题**；文档里加一句「选项次序已打乱，避免答案集中在某字母」向用户说明，否则用户会怀疑出题质量。
6. **答案必须用换算法独立复核**：PS 题用 `Fraction`/暴力枚举/组合计数重算 → 再把算得的值**定位到选项文本**（`opts.index(text)`）核对答案字母指向的就是该值；DS 题用构造反例/网格穷举/枚举验证两个条件各自的充分性，推出字母再与卷面比对。另加结构自检（题号 1—30 连续、每题 5 个互异选项、DS 每条含两个条件、来源配比、A—E 各 6 题）。任一 FAIL 不许交付，回执写明「30/30 通过」。
7. **产物文件**（`98 hermes/`，换日期改数据模块即可复用）：数据 `mba_q_ps_<YYYYMMDD>.py` + `mba_q_ds_<YYYYMMDD>.py`、建卷器 `mba_q_build.py`（读数据渲染，输出三份）、复核器 `mba_q_verify_<YYYYMMDD>.py`、入库器 `mba_q_ingest_<YYYYMMDD>.py`。**建卷器与复核器要一起重跑**：改完选项次序后必须重跑复核，否则字母校验会用到旧分布。
8. **入库**：三处落位（98 hermes / `JesseYoung/MBA/练习/` / `raw/sources/`）+ 追加 `wiki/log.md`。**日更文件不进 hub 资料地图逐条列**：hub 里只留一条「每日 30 题（日更）」分组 + 日更规则（首套挂链接、写清命名规则）；只有 hub 自身要改版时才递加版本号，避免每天 bump 一次 hub。建卷器 `mba_q_build.py` 的输出路径常量必须写死 `JesseYoung/MBA/练习/`，改目录后要重跑生成器并用 `md5` 对比已发布文件确认内容未变。
9. **回执绝不剧透答案**：给路径 + 规模（行数/字节数）+ 复核结论 + 「今天第一步动作」（如「先限时 60 分钟做第 1—20 题」）。答案在文件末页，聊天里只说存放位置与做法。用户隔天说「再来 30 题」时，直接换日期生成，不要再确认规格。

## 英语每日练（完形填空 + 阅读理解）日更

用户口径（逐字）：「再帮我生成一下今日的MBA英语完形填空和阅读理解，我每天准备练习30道数学题以及阅读理解」——与数学日更并列的第二条常驻日更线，规格固定，别再问。

1. **体量**：完形填空 20 题 + 阅读理解 Part A 2 篇 × 5 题 = **30 题**。**素材优先用历年英语二真题原文** —— 用户口径（逐字）：「你今天给我生成的MBA英语试题是MBA考试的吗？感觉过于简单了啊…哪怕找一些历史的真题也行，不用近五年的真题，找年代久一点的真题」。所以年份**从 2016 往前推**（2015、2014…），**避开近五年**；同一年原卷 Part A 有 4 篇，一次取 2 篇（第 21—30 题），另 2 篇留作下一套并在卷首写明还剩哪几篇。真题确实抓不到时才退回「按命题风格自编」并照第 6 条声明。
2. **文件名**：`MBA英语每日练_YYYYMMDD_v1.0.md`（同日重做递加 v1.1），与数学卷同落 `JesseYoung/MBA/练习/`。
3. **单文件、答案在最后一页**：第 1 部分 使用说明 → 第 2 部分 完形填空（题面 + 20 行选项表）→ 第 3 部分 阅读理解 Passage One/Two（每题 `- A.` 四个选项）→ `---` → **第 4 部分 答案与解析**，子节固定为 4.1 答案速查 / 4.2 完形逐空解析 / 4.3 阅读逐题解析（含定位句）/ 4.4 全文译文 / 4.5 生词与短语（职场高频）/ 4.6 长难句拆解 / 4.7 错题与生词本。
4. **速查表用转置排版**：`| 题号 | 1 | 2 | … | 10 |` / `| 答案 | B | A | … |` / `| 正确词 | spends | invest | … |`，每 10 题一块；阅读块只有题号 + 答案两行。表下写**答案分布**（A/B/C/D 各几题）与自我判分档位（完形 20×0.5 + 阅读 10×2 = 30 分制，≥24 / 18—23 / ≤17 三档对应动作）。
5. **选项次序打乱**：完形正确答案 A/B/C/D 大致均分（如 7/8/8/7），并在速查表下声明分布，避免答案聚堆。
6. **文档头声明（二选一，必须写清）**：①**真题卷** → 「素材取自 `<YYYY>` 年考研英语二真题原文：Section I 完形填空 20 题 + Section II Part A 的 Text X、Text Y（第 21—30 题），**答案为官方答案**」，并写明**选年口径（避开近五年）**、**原卷还剩哪几篇留作下一套**、**各版本真题册选项次序可能不同 → 答案字母以本文件选项顺序为准**；②无真题可用才退回自编 → 「均为按英语二命题风格自编的仿真练习，不冒充真题原文」。
7. **交付前独立脚本复核**（任一 FAIL 不许交付）：①答案 1—30 齐全；②完形「正确词」行的词 == 该题选项表里对应字母指向的词（0 不一致）；③阅读速查表字母 == 4.3 解析标题 `**21. C` 的字母；④实际答案分布 == 文档声明的分布；⑤所有题干在 `# 第 4 部分` 之前；⑥21—30 每题恰好 `- A./- B./- C./- D.` 四个选项；⑦完形全文里 `[1]…[20]` 共 20 个空位。回执写「30/30 通过」，**不剧透任何答案**。
8. **hub / 入口页**：英语日更与数学日更共用一条 hub 分组规则 —— hub 里新增「英语每日练（完形 + 阅读）」行 + 英语日更规则（命名、题量、答案在末页），并把「每天怎么用」加一步英语日课；`练习总览` 新增「英语每日练：命名与日更规则」一节。首套挂链接，后续**新日期**的日更不再 bump hub/入口页。**但首套被替换（如自编改真题）时要 bump**：hub 的英语日线 / 日更规则 / 对照表 / 待办 / 版本记录、入口页（`练习总览` 递加版本）、全库引用一起改，否则主文档还指着已删的卷子。
9. **工作副本**：分片草稿 / 出卷器落 `98 hermes/`，前缀 `eng_<YYYYMMDD>_p*.md`。题面与解析分片写（避免长文截断），最后合并为单一成稿再入 vault。

## 真题解析抽生词（生词汇总类产物）

## 多份练习卷融合（3 合 1 合卷）

用户口径（逐字）：「我看你现在是 4 个文件，把 3 个考试相关的帮我融合到一个文件，要不然太冗余，答案解析放在最后就行」——**一份卷子只占一个文件，题面在前、答案解析统一放文末最后一页**，永不拆「试卷版 / 解析版」。

1. **版式**：使用说明 → 同源题速览（哪几题重复可跳过）→ 考点分布 → 第 1 部分 答题卡（各卷一块）→ 第 2—5 部分 各卷题面 → **第 6 部分 答案与解析（速查表 + 逐题解析，B 卷按原模块「一、问题求解 / 二、条件充分性判断」分块）** → 第 7 部分 错题诊断。融合后层级：卷 = `##`，模块 = `###`，逐题 = `#### 第 N 题`；A 卷与 B 卷题号各自从 1 连续。
2. **融合不是重写**：题干、选项、答案数值一字不改，只重排 + 去重 + 补一份合卷使用说明。
3. **删源文件前必须做「内容行全覆盖核对」**：`git show <上一条 commit>:"<旧文件路径>"` 取回旧版，逐行归一化（剥 `#`、剥 `**`、全角空格→半角、`\s+` 压平）后在合卷全文里查存在性；允许不匹配的**只有封面 / 使用说明 / 分节标题**，任何题干、选项、答案、解析行不匹配就回查建卷器。这是证明「融合没丢内容」的唯一证据 —— 别只看合卷行数。
4. **入库走全套**：合卷进 `JesseYoung/MBA/练习/` + `raw/sources/` 镜像；删掉旧 3 份文件及其镜像；入口页 `练习总览` 递加版本并写「3 合 1 变更」段；hub 递加版本（资料地图 3 行并 1 行、资料总数递减、变更行 + 版本表 + 待办勾选）；顺手修只被相关文件引用的旁支页（如公式速查的配套链接）并递加其版本。
5. **`[[ ]]` 不许悬空**：全库扫旧 basename（`grep -rn --include=*.md`，排除 `raw/sources/`），命中即改；hub 自己的**历史变更行**保留旧链接属正常（库里既有惯例），但正文 / 资料地图 / 索引 / wiki 页一个旧引用都不许留。

## 生成与验证流程

1. 数据文件分批写（大数据拆片），**每片写完立刻自检**：行数 + 能否 import + 记录条数（例：每 Unit 50 词、共 21 个 Unit）。
2. 跑生成器，**打印每个产物的行数与字节数**（`wc -l -c` 或脚本内自报）。
3. 交叉核对条数（这些数字要进回执，必须真实）：
   - `grep -c "^## Unit "` = 单元数；勾选框计数 = 总词数（21 × 50 = 1050）
   - 逐日表按行区间数行：`awk 'NR>=79 && NR<=157' plan.md | grep -c "^| [0-9]"` = 天数（75）
   - 生成器里 `grep -c` 到 0 行不代表没有，逐日表行格式可能是 `| 75 | 12月18日 |`，先 `sed` 一段看真实格式再数
4. HTML 面板用 `browser_exec` 打开 `file://` 实测，见 `references/interactive-checkin-panel.md`。
5. 交付前清掉测试数据（`localStorage.clear()`），别让用户打开就看到假进度。
6. 回执必须带**真实核验结果**（条数/行数/实测行为），不能只写「已完成」。

知识点↔真题对应表的完整做法（数据模块骨架、文档骨架、覆盖率自检命令、交付前核对清单）见 `references/knowledge-point-question-mapping.md`。

## 回执格式

- 一句话说明做到了什么 + 交付物表格（文件 | 内容 | 规模，规模用真实行数/字节数）。
- 若做了拆分，附「分开对照表」：打卡面板 / 每日时长 / 打卡项 / 掉队表现 分别是什么。
- 「实测结果」小节列出跑通的证据（单元数、天数、面板勾选后的统计文字）。
- 面板类产物直接内嵌预览：`::preview{file="<绝对路径>.html"}` 单独一行。
- 结尾给一个小到不可能不做的**第一步动作**（如「今天只过 Unit 1，15 分钟」），再按 SOUL.md 收尾一段 English time（1–2 句 + 中文释义 + 例句）。

## 坑

- **新建/迁入子目录要一次做完四件事**：`git mv` 文件 → 该目录落一份入口索引（`type: index`，写清「这里放什么、命名规则、不放什么」）→ hub 递加版本号并把新目录挂进资料地图 → 全库批量改写引用 + `raw/sources/` 镜像 + `wiki/log.md`。只建目录不挂链，用户会找不到东西。
- **真题卷的选项与答案必须取自同一页**：同一道题在不同网站/真题册上 A/B/C/D 会**对调**（例：2016 Text 1 第 22 题，A 站印 D=interest、B 站印 B=interest）。从 A 站抓题面、B 站抄答案字母必错。做法：①选项与答案同源；②逐个校验「答案字母 → 该字母的选项文本」是否等于解析点名的正确词；③再用第二个站（中国教育在线 `kaoyan.eol.cn`、希赛网 `educity.cn`）交叉核对同一年的字母。真题**不重排选项**，A/B/C/D 分布不均（如 5/5/5/5 与 3/2/3/2）属正常 —— 但必须在速查表下声明真实分布，否则会被当作出题失误。
- **用户说「重新生成」= 同日递加版本号 + 删掉被取代的旧版**：v1.0 → v1.1，正文与 `raw/sources/` 镜像**一起删**，同时把全库指向旧版的引用（hub / 入口页 / 书签 / wiki 页）改到新版 —— 只加新版不删旧版，用户会打开错的那份卷子。**跨日期**的旧卷才按库内惯例保留。
- **真题里的中文译文不要照抄网络版**：公开解析页的译文常错译（例：把 "Firms seem to invest more in places where most people are relatively happy" 译成「乐于投资快乐员工所在的部门」）。译文自己写，网络译文只用来核对术语；解析同样重写（写「考点 + 定位句 + 同义替换 + 陷阱项」），不要把源页的碎句照搬。
- **`.obsidian/workspace.json` 是 gitignore 的**（`.obsidian/workspace*.json`，`git ls-files` 查不到）：改完 `git status` 仍干净属正常，不必找「为什么没提交」；它只影响本机已开标签页，Obsidian 自己会清理。

- **数据片截断会静默通过**：某片只剩 10 行时生成器照样跑出结构完整、行数看起来正常的文档，只是内容缺了一整段。所以必须逐片自检行数与记录数，不能只看成品行数。
- **面板日期键格式必须与数据键一致**：数据用 `"10-5"` 这种短键时，JS 今日判定要统一走 `todayKey()`，别用 `toISOString()` 派生的 `todayISO()`，否则「今天」永远定位不到第一天。
- **表格 caption 位置**：`<caption>` 必须是 `<table>` 的第一个子元素，放在 `<thead>` 后面会被浏览器丢弃（表现为 `document.getElementById('cap')` 取到 null 或文字为空）。
- **没安排的科目不算欠账**：当天无该项时显示「—」并不计入分母（0/3 而不是 0/4），否则用户永远打不满、连续天数归零。
- **语料/数据的标签键名可能混用两套命名**（`y2016`/`y2017` 与 `math_2019`/`math_2022` 并存），硬编码标签名访问必崩 `KeyError`。访问前先打印真实键（`sorted(corpus.keys())`），再取数。
- **生成器的渲染字段名必须与数据模块的键名逐一对齐**：先内联 python 打印一条数据的键（`GAPS[0]`、`CH[0]['secs'][0]`）再写渲染段，否则首跑必是字段对不上导致的 exit 1。
- **补数据写成独立模块，别 patch 大文件**：几十 KB 的案例数据文件上做定向 patch 既脆又难核对；新增考点写 `*_extra.py`，由生成器 `from ... import EXTRA` 后与主数据合并（正文与索引要一起合并，别只改一处循环）。
- **patch 列表/字典字面量里的元素时，把收尾的 `]),` 一起纳入匹配**：old_string 只覆盖元素内容行时，原来的收尾括号会留在原位，后面那行变成孤儿语句 → SyntaxError，文件当场坏掉。发现后立刻删掉孤儿行。
- **回执里引用的文件名必须 `ls` 实测**：给用户的附件名/库内路径若凭记忆写（如把「试卷版」写成「试题版」），用户点开发觉文件不存在，整份交付的可信度就没了。落盘+回执前一律以磁盘实测文件名为准。
- **新增成套练习卷/题库类产物也要走完整入库流程**：不只写进 `JesseYoung/MBA/`，还要 ①镜像进 `raw/sources/`；②挂进 hub（版本号递加 + 全库批量改写引用 + `.obsidian/bookmarks.json` 里的旧路径一并改，否则书签指向已删文件）；③追加 `wiki/log.md` 条目。
- **核对「每题几个选项」时，切片必须切到下一题干为止**：按 `**21.**` 取字符窗口（如取 600 字符）会串到下一题，把下一题的选项也算进来，报出「7/8 个选项」的假 FAIL。正确做法：先收集所有题干位置，每段的结束位置 = 下一题干起点（最后一题取到第 4 部分起点）。
- **英语速查表是转置表**（`| 题号 | 1 | 2 | … |` / `| 答案 | B | A | … |`），不要用 `^\|\s*(\d+)\s*\|\s*([A-D])\s*\|` 这种逐行正则去抽，会得到 0 行并误判「速查表缺失」。按「读到 `题号` 行建列索引，再读 `答案`/`正确词` 行按列取值」解析。
- **校验命令会静默掐断 `&&` 链**：`grep -c` 命中 0 时返回 exit 1，后面串着的 `git add/commit/push` 全部不执行，而终端只显示 exit 1、看起来像「无输出」——校验与提交**分步跑**，或写成 `grep -c ... || true`。同理 `cd` 进含空格的目录（`99-软件工厂/98 hermes`）必须加引号：`cd "$HOME/Documents/work/smardaten/smardatenCorp/99-软件工厂/98 hermes"`，否则第一步就断。
- **重跑生成器后必须重新 `grep` 产物的版本号**：批量改写过的 hub 链接会被重跑覆盖回旧值（生成器常量没同步时），所以「产物已改好」的结论必须以重跑之后的 grep 结果为准，不能以改写当时的 grep 为准。
- **改生成器后必须重跑并复核产物字节/行数**，不要凭第一次写入的结果（早期 `write_file` 只报 6 行而实际内容更大的情况出现过）。
- **融合脚本报 `chunk not found: <标签>` 基本是标签写错了**：取块时容易写「一、逐题解析」这种自己以为的标题，而原文标题是「一、问题求解」——先打印源文件所有标题行，再拿真标题写取块标签。
- 大文件（1000+ 行）不要一次读写核对全文，用 `grep -c` / `awk` 区间 / `tail` 抽查头尾与关键段落即可。
- **查「残留旧引用」不能只看 `grep -rl` 命中**：同一条命中常常是别的文档自己的版本号（生态页/log 里的 `v1.3`），先 `grep -n` 看命中行，再决定改不改——否则会去「修」根本没引用你的文件，还把历史记录改坏。
- **校验 wikilink 时先剥掉转义反斜杠**：表格里写的链接是 `[[X\|别名]]`，正则抽出的目标带 `\|`，直接与文件名比对会全部报 MISS，白白查出「一场故障」。
- **删掉被替代的旧版本文件后，`.obsidian/workspace.json` 里仍留着旧路径**（`lastOpenFiles` 不带扩展名）——Obsidian 自己会清理，别花时间「修」；但若 Obsidian 正开着那个已删文件，就让它改指新版本，或直接告诉用户重开一次。
