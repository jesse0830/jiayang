# 中文文档口径与交叉引用审计（多轮改稿后必跑）

来源：`业务交付提质增效方案2026.9` 第三、四轮优化（2026-09-16）。适用对象：任何经过删节、章节合并、重新编号的中文汇报/方案类文档。
目标：改稿不制造新的自相矛盾 —— 编号、引用、计数断言三处最容易随结构漂移。

## 1. 断言计数审计（「以下N类」「N 个原则」）

正文里凡是「以下N类／N个／N 个原则／N 条」这类自报数量，都要与紧随其后实际列出的条目数对齐。

```python
import re, docx   # 逐节扫描：把节内文本拼起来再数
num = {'一':1,'二':2,'三':3,'四':4,'五':5,'六':6,'七':7,'八':8,'九':9,'十':10}
for sec_title, sec_text in sections:            # sections = [(节标题, 全节文本)]
    for mt in re.finditer(r'以下([一二三四五六七八九十]+)(?:类|个|项|种|条)', sec_text):
        claimed = num[mt.group(1)]
        tail = sec_text[mt.end():]
        # 统计后续序数条目：第一/第二…、①、1.、（1）、原则一…
        items = len(re.findall(r'(?:第[一二三四五六七八九十]+|[①②③④⑤⑥⑦⑧⑨⑩]|^\s*\d+[.、]|原则[一二三四五六七八九十]+)', tail[:1200], re.M))
        if items and items != claimed:
            print(f'[计数不符] {sec_title}: 声称 {claimed} 实列 {items}')
```

**窗口教训**：`tail` 取太短（本次先取几百字符）会漏掉节后半段的条目 —— DE 侧先只数到 4 条，扩窗后才见第「第五、第六优先级」，实际 6 条。实测与自己的判断不符时，回去看全节，不要就着窗口下结论。

本次审计结果（可作为「审计到位」的范式）：
- 「以下五类能力」→ 实列 6 条（第一～第六优先级）→ 真笔误，用户批准后改「六类」
- 「围绕三个原则调整」→ 实列 4 条（原则一～四）→ 真笔误，改「四个原则」
- AE 侧「以下三类」→ 实列 3 条 → 一致，保留并在结论里点名
- 3.2.7「建议形成以下四类」→ 对应表格在原文就缺失（属已知 8 处内容缺失）→ 标「无法核对」，不猜
- 全量结论：**全文只有这 2 处是真笔误**

流程要求：改动前把候选写进交付的「优化说明与问题清单」，用户明确批准（本次回「可以改」）后才动手；数字口径不擅自改。

## 2. 交叉引用审计（第X章 / x.y / x.y.z）

结构调整（合并章、改层级、三段号）之后，全文扫一遍引用目标是否还指得对：

```bash
grep -nE '第[一二三四五六七八九十]+章|第[一二三四五六七八九十]+、第|\b[0-9]+\.[0-9]+(\.[0-9]+)?\b' 全文导出.txt
```

本次 6 处全部按新三段号重写（示例：「后面第四、第五章可以进一步建立」→「后面 2.2、2.3」；「与 6.3 的第三、第四优先级」→「3.1.3」；「根据第三章定义的 C1、C2、C3、S 类」→「2.2 定义」）。改完再扫一遍，**确认零残留旧章号** —— 引用改成绝对三段号后，才对后续结构变动免疫。

注意：rebuild 脚本每轮都从**源文档**重建（不做增量），所以替换用的 `old_string` 必须取自**原文文本**；拿新编号/新措辞去替换原文里不存在的串会静默无改动（本项目犯过一次，白跑一轮）。

## 3. 编号层级：部分 → 子主题 → 节

合并后连号会让汇报没法定位（现状部分 31 个节 → 2.1～2.31）。用户认可的形态是三段号：

```
■ 二、现状与问题            ← 部分（黑体 16pt）
      2.1 当前交付模式和效能分析   ← 子主题（14pt，沿用用户原章名）
            2.1.1 …               ← 节（12pt）；节内小标题 11pt
```
目录只到第三级（节）。子主题名一律沿用原章名或用户消息原话，**不自创**——自创名字还会污染零丢失校验（被标 missing）。

## 4. 残留指代问题（交付时单列，不动正文）

1. 「本章核心结论」这类相对指代在多轮合并后指代不清（本次 4 处：2.3.9 / 2.4.9 / 3.1.7 / 3.2.12）→ 建议改成「2.3 核心结论：人员能力与任务匹配」式绝对编号。
2. 子主题之间结论节有无不一（多数子主题有结论节，2.1、2.2 没有）→ 建议补齐，把该部分问题收敛成一句话。
3. 正文条目序号「一、二、三」与一级标题格式撞车 → 建议改「（1）（2）（3）」。

这三类都写进「我改了什么 / 留给你定」的后者，不擅自改。
