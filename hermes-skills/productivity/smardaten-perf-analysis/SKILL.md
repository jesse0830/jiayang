# 软件工厂行为绩效考评解析

## 表结构（每月一份，列固定）

数据目录：`99-软件工厂/02 绩效/2026年/`（按月分子目录 5月/6月/7月/8 月，注意「8 月」带空格）。

- 前 3 行是标题/表头，**数据从第 4 行开始**。
- 列索引（0-based，openpyxl `values_only`）：1=工号 2=姓名 3=员工类别 4=招聘类型 5=一级部门 6=二级部门 **7=三级部门** 8=入职日期 9=离职时间 10=核心绩效目标得分 11=人才观得分 12=排序 **13=绩效结果** 14=员工自评 15=部门评语。
- `工号` 列可能是中文（如「南通」）而非数字。
- 表头行里 `title = rows[0][10]` 是「2026年X月月度绩效考评」。

```python
import openpyxl
ws = openpyxl.load_workbook(path, data_only=True)[sheet]
for r in ws.iter_rows(values_only=True):
    if len(r) > 13 and r[2] and str(r[2]).strip() != "姓名":
        name, dept, grade = str(r[2]).strip(), str(r[7] or "").strip(), str(r[13] or "").strip()
```

## 踩坑（都是实测踩过的）

0. **重存会把表改坏**：2026-10-01 用户把 6月-All 重存后从 60.5KB 变 24.0KB，**附带 sheet 被删，公式失去引用 → 12 格「绩效结果」变成 `#REF!`**（刘亚朋/周婷婷/夏思越/孔雨晴/孙堂颖/张凤凤/戴忆婷/朱锦秀/程云中/谈爽/邵叶强/陈皓）。这是**最危险的一类差异**：周婷婷、孔雨晴的 6月 A 就在其中，当空值算会让两人从「≥3A」掉到 2A。
   - 检测：`str(cell).strip()` 落在 `{"#REF!","#N/A","#VALUE!","#DIV/0!","#NAME?","#NULL!","#NUM!"}` 里即视为缺失，**不要当成一个等级**。
   - 修复：双源交叉验证后再用 —— ①旧版本缓存值（重存前的同文件）；②部门拆分表 `6月/2026年6月度行为绩效考评-软件工厂.xlsx`。两源一致才采用，并在产物里标注「修复值」。
   - 每次拿到「最新」表都要**先和上一版逐格 diff**（差异往往不是业务改动而是损坏），别默默重算完就报结论。
1. **6月-All 原本有三个 sheet**：Sheet1=6月评级（用这个）；**Sheet2 标题写着「2026年5月」，是南通/驻场团队的 5月表**；**Sheet3 是自评汇总，55 行全部无评级**——别把它当评级数据，否则 6月人数会从 72 虚高到 127。（重存版只剩 Sheet1。）
2. **部门拆分文件（`-DE`/`-IE`/`-配置开发部`）与合并版有评级冲突**：5月 周婷婷/孙堂颖/夏思越/璩增辉、7月 黄京徽/璩增辉、8月 黄京徽 共 8 处。口径规则：**以根目录合并版（最新保存的那份）为准**，冲突单独列表请用户裁定，不要静默合并。
3. **同一个人可能在同月出现两次**（部门调动，如黄京徽 7月同时在两个 sheet），别直接累加。
4. **`6月/2026年6月度行为绩效考评-软件工厂.xlsx` 文件名是 6月，里面那张 sheet 标题却是 5月**——按 sheet 标题判月份，不要按文件名。
5. 7月根目录文件只有一个名字叫 `Sheet2` 的工作表，别以为缺 Sheet1。

## 调薪资格测算（用户关心的主线）

规则（用户 2026-10-01 最终口径，**以此为准**）：**连续 2 个季度窗口内累计 ≥3 个 A，且过程中不能有 C**。
- 2026 年语境：Q2+Q3 = **4-9 月**窗口（9 月绩效未打时做预判）；用户原话「评级是按照连续的2个季度，所以是4-9月份有三个A并且没C」。**不要再写「连续 6 个月」**（那是早期措辞，已被用户纠正）。
- 窗口 = 连续 2 个季度；每季度末出表后判一次，每年从 Q2 起算第一个窗口。**看目标季度往前推 2 个季度，不是看全年累计。**
- 9 月（窗口最后一个月）未评时，输出按「已达标 / 临界-9月需A」分层，并给**势头**标签：近 2 月无 A = **降温**（最易惯性给 B 而错过线，如季智/王佩琪/王晴），最近 1-2 月刚拿 A = **最热**（顺势倾斜成功率最高，如胡学生/杨军/汪靖/孙堂颖/戴忆婷）。
- 四组输出（用户要的就是这个结构）：
  - **A 组 已达标**（窗口内 ≥3A 且 0C）→ 下一个月不拿 C 即成立；
  - **B 组 临界**（2A 且 0C）→ 下一个月拿 A 即达标，**这是用户最关心的名单**；
  - **C 组 已出局**（窗口内有 C），典型如 2A+1C 的王俊 —— 要单独点出来，否则用户会以为他也在临界组；
  - **D 组 未达标**（A≤1）。
- **两个必须请用户/HR 定口径的模糊点**，不要自己拍：①窗口是否要求**完整参与考核**（新入职者如汪靖 2026-05-13 入职、7/8 月连 A，能否 9 月就成立）；②窗口内出现 C 后，是**从最后一次 C 之后重新起算**（王俊 5 月 C → 下个窗口 6-11 月）还是**自然年作废**（等 2027 年）。
- 附带核查：**试用期**员工是否参与调薪；**「员工类别」可能被录错**（顾睿 4-7 月「正式」、8 月变「试用」，入职日 2023-04-24）；**驻场人员工号写的是地点**（孔雨晴=「宿迁」、杨军=「南通」）。
- 部门口径：取**5 个月内最近一次非空值**（4-5 月有填、6 月起多为空），否则人数会漂（申梦娇、王佩琪会落到「未标」）。

## 统计与产物约定

- 参考实现：`~/.hermes/cache/scratch/perf_final.py`（抽取+统计）与 `perf_report.py`（md+xlsx 产物）。
- 本地 Python 用 `/usr/bin/python3`（已装 openpyxl 3.1.5）；Hermes 自带 python 没有 openpyxl。
- 关键指标：A/B/C 计数、有效月数、**最长连续A**（比累计数更能说明稳定性）。
- `A≥3` = 用户口中的「超过2个A」。同时给 `A=2` 次高潜名单和 `C≥2` 名单。
- 产物落 `99-软件工厂/98 hermes/`，文件名带窗口区间与版本号：`软件工厂绩效分析_2026年4-8月_20261001_v1.1.md/.xlsx`（旧「6 个月」口径）、**`软件工厂绩效分析_2026年4-9月窗口_20261001_v1.2.md/.xlsx`（现行口径；7 个页签：调薪预判 / 季度视角 / 月度汇总 / 部门汇总 / 出局与重算 / 数据质量 / 修复参照）**。v1.2 生成器 = `perf_v3_report.py`。
- 出局者的重算起点 = **最后一次 C 的次月**（滚动口径）+ 「季度口径：下一个完整窗口从 10 月起算」两列并列给出，让用户自己选。
- **脚本结果必须落盘再用 `read_file` 读回**：terminal/execute_code 的长输出会被 Hermes 压成「1 lines output」，只有写文件才拿得到。
- 数字不用千分位分隔符。
