# 劳动合同续签 / 转正审视

## When to Use

- 用户发来「劳动合同续签审视」xlsx 或转正名单，要求出审视意见 / 续签理由；
- 用户给出若干员工的绩效与项目经历，要求按四维度（能力/意愿价值观/相对/经营）定性；
- 需要把多维评价压成可直接粘进 Excel 单元格的成段文字。

厂长（杨嘉阳）每轮续签、转正审视用。输入一封 xlsx 名单 + 软件工厂绩效库，产出 ①审视意见 md（v1.x 带版本号）②Excel「续签理由」列用的成段文字。

## 流程

1. 读名单 xlsx（工号/姓名/性别/年龄/政治面貌/职级/司龄/工作地/入职日/学历/签约与发薪主体/合同到期日）。openpyxl 在 `execute_code` 里常输出降级 → 脚本写 `/tmp/rd.py`，用 `terminal` 跑 `PYTHONPATH= python3 /tmp/rd.py`。
2. 绩效反查：读 `98 hermes/_perf48_raw.json` 的 `d["rows"]`，按 `r["name"]` 精确匹配（直接 grep 姓名常不命中）。字段：`name/dept/M/A/B/C/n/month_stats/alt`。输出格式固定 `姓名 | 部门 | 4月 | 5月 | 6月 | 7月 | 8月 | 9月`，缺失写「表损坏 / 未找到」，不猜。
3. 算部门内相对位置：拿过 A 人数与占比、2A+ 人数、全 B 无 A 无 C 人数、拿过 C 人数、记录不足 4 个月人数；再算全厂 0A 占比、0A0C 占比、人均 A 数。这些数字是「相对维度」的锚，别凭空写「中等偏上」。
4. **先向主管要结论定调，再动笔。** 不要自行推定「附条件续签 / 压降 N 人 / 某人不续签」——这类推断一经写进文档就会被打回重写。
5. 写 md 审视意见：结论速览表 → 绩效底稿＋部门分布 → 逐人四章（①②③④维度各一段带加粗结论）→ 续签结论＋后续管理动作 → 「关于从严的说明」→ 待办。
6. 另出「Excel 填写版」：每人**一段**成段文字，把四维度串成 4 个分句（`能力维度：…意愿与价值观维度：…相对维度：…经营维度：…结论：…`），**不要 markdown 标题、不要项目符号**，否则粘进单元格会散。

## 四维度口径（用户原文，照抄不改）

1. **能力维度**：长期绩效表现与潜力。
2. **意愿与价值观维度**：是否内耗，发牢骚、讲怪话，增加管理成本。
3. **相对维度**：团队中属中等偏上还是下游。
4. **经营维度**：公司要求每个人的贡献 ＞ 成本，是否 overpay，投入产出是否值得。

整体导向：实事求是、走向规范、理性 ＞ 感性。**「从严」只落在标准、问题暴露、回报上，不落在清退达标员工上。**

## 硬规则（踩过的坑）

- **「全 B」不等于能力弱**：A 覆盖率通常只有二三十%，全 B 是多数人常态。要写清 B 是「交付质量稳定、无返工无投诉」的 B，0 个 A 反映的是没去申报超额任务，不是能力不足。
- **短板表述必须与项目实证互不矛盾**：若某人有硬实证（独自驻场一年零投诉、任 TL 数个月带团队抗压），**禁止**写「积极性差 / 不想发展 / 不愿干 / 挑活」，只能收窄为「**不主动申报超额任务、不主动表达晋升诉求**」——归到自我争取层面，不归到责任心层面。
- **潜力判断区分「没被安排」与「不能干」**：实证过的能力（如 TL 经历）若之后未被继续使用，写成「能力已被验证、只是未被安排」，并给下一周期明确的使用场景。
- **「第三次签约前须有 1 个 A」这类门槛要给出口**：补「或等值可量化成果（独立支撑一个项目、担任 TL 带团队满 6 个月等重投入经历可计入）」，否则干重活的人永远换不到 A，条款成死结。
- **顺手识别单点风险**：单人长期驻场一个项目＝项目断档风险，写进待办（安排 backup 轮换或远程支持），与个人评价分开谈。
- **合同到期日要换算成剩余天数并前置**：到期前 10 天内未启动续签会形成事实劳动关系风险。
- **签约主体可能是第三方（如麟软）**：续签文本由主体公司出具，工厂只出审视意见，写进待办。
- 文件落 `…/99-软件工厂/98 hermes/`，文件名带 `_YYYYMMDD_vX.Y.md`，版本号每次改动递增（v1.0→v1.1→v1.2），文档头同步写变更说明。

## 产出清单

- `劳动合同续签审视_<部门>-<范围>_<YYYYMMDD>_vX.Y.md`
