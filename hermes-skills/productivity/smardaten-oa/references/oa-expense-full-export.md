## ⚠️ 头号陷阱：antd Tabs 未激活面板仍在 DOM
「员工报销」是 antd Tabs 三页签结构，**未激活 tab 的表格不会被销毁，仍留在 DOM 里**。

错误做法：
```js
document.querySelectorAll('tr.ant-table-row')   // ❌ 三张表 + 累积翻页一起抓
```
实测后果：行数从真实 109 虚高到 **228**、表头重复 3 次、金额重复累加。且切换 tab 后旧面板的行还在，翻页也会串。

正确做法 —— 先定位 pane，再在 pane 内抓行、pane 内翻页：
```js
const panes = document.querySelectorAll('.ant-tabs-tabpane');   // 实测 3 个，各带独立分页
const pane  = panes[tabIdx];                                    // 0=出差 1=个人 2=招待旧
const rows  = [...pane.querySelectorAll('tr.ant-table-row')].map(r => [...r.querySelectorAll('td')].map(td => td.innerText));
// 翻页同样限定 pane：
pane.querySelector('.ant-pagination-next').click();
// 页码校验也用 pane 内选择器：
pane.querySelector('.ant-pagination-item-active').innerText
```
- 取单元格文本用 **td.innerText**（body 层 innerText 取不到表格，属正常）。
- 每个 tab 分别抓、分别落盘（如 `emp2_出差报销.json`），不要混一个文件。

## 抓完必做的三项校验
1. **唯一编码数 vs 行数**：招待新模块 41 行 → 40 唯一编码，说明有重复行，必须按编码去重后再统计。
2. **行数 vs 分页总数**：差额 >0 说明漏页。
3. **与「我发起的」交叉核对**（这一步能发现归类错误）：
   - 员工报销 tab 是**单据视角**，我发起的是**流程视角**（多含"出差申请"申请单 90 条，不计入报销）。
   - "我发起的"里类型为"费用报销"的 101 条中，有 **16 条编码实际落在招待报销(旧) tab 里** —— 旧流程名称导致误标，应归入招待旧单，**勿重复计数**。
   - 出差/个人 tab 内有 5 条老格式编码（形如 `20240228-126`，日期+序号），是真实早期单据（天津代表处/城市运营部时期），保留。

**2026-09-17 全量结果**：84+6+19+40 = **149 笔 / 155492.34 元 / 2024-03 ~ 2026-09（30 个月）**。

## 分析维度（用户认可的一套）
总览 KPI → 按类型 → 按年度 → 按状态 → **承担主体 Top10（项目成本视角，最有用）** → 大额集中度（≥1500 的单占总额比）→ 月度趋势 → 出差单笔均值变化 → 招待新旧模块对比 → 未结清账龄 → 异常结束单核对。

## 交付形态（三件套）
1. Excel 多 sheet：`98 hermes/OA报销数据全量分析_YYYY-MM-DD.xlsx` —— 全量明细 / 汇总-类型 / 汇总-项目主体 / 汇总-状态 / 月度趋势 / 年度汇总 / 未结清明细
2. HTML 看板：`98 hermes/OA报销数据看板_YYYY-MM-DD.html`，聊天里用 `::preview{file="绝对路径"}` 内联展示（KPI + 月度柱状 + 类型/项目横条，用 var(--foreground) 等主题变量，不设自己的背景字体）
3. 报告 md：`98 hermes/OA报销数据分析报告_YYYY-MM-DD.md`

## 报告写作口径（用户偏好）
- 数字**不用千分位分隔符**（写 155492.34，不写 155,492.34）。
- **现象与判断分开**：如"招待新模块上线后月均金额从 1451.15 涨到 3137.29"是事实，必须并列给出可能归因（新流程把历史漏报补录 / 活动真实增加 / 口径变化），**不要直接定性为费用失控**。
- 结论要落到可执行动作（推掉 319 天老单、抽查高位月份做归因、建项目级招待台账…）。
- 组织变迁可从"二级部门"列读出（项目产品四部 → 项目产品部 → 软件工厂），与 2026-04 上任软件工厂吻合。
